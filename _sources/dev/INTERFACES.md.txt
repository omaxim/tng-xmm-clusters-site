# INTERFACES: the contract between the stages

The code is the contract wherever both exist: `src/tngxmm/schemas/`,
`src/tngxmm/config.py`, `src/tngxmm/core/`, `src/tngxmm/cli.py`,
`src/tngxmm/cites.py`. This document explains it and records the decisions
the code cannot express. A change of a table, an id, a file name or a seed
message is a change of the contract: it goes with a new version of the package
(`CHANGELOG.md`) and with the tests that pin it.

## 1. Package skeleton, CLI and registration points

- One installable src-layout package `src/tngxmm/`, Python ≥ 3.10, MIT.
  `pyproject.toml`: `[tool.kedro] package_name = "tngxmm"`, `source_dir = "src"`;
  console script `tngxmm = tngxmm.cli:main`. Importing `tngxmm` needs only
  `click`; every scientific import (numpy, astropy, pandas, kedro, torch) is
  deferred to the function that uses it. A unit test enforces this.
- **Frozen stage list** (`tngxmm.STAGES`, data-flow order):
  `ingest sim instrument donors obs photometry massfit bank embed ml viz` (`ingest` added on the branch
  `multisim`, DECISIONS "Multi-simulation pipeline").
  Kedro namespace = stage, so node names read `massfit.fit_hydrostatic`.
- **Per-stage registration points** (owned by the stage's workstream; no
  shared-file edits needed to add things):
  `src/tngxmm/<stage>/cli.py` (click group named after the stage, exported as
  `group`), `src/tngxmm/<stage>/schemas.py` (stage-internal `TableSchema`s in
  `TABLES`), `src/tngxmm/<stage>/pipeline.py` (`NODES` list +
  `create_pipeline()`), `conf/base/catalog/<stage>.yml`,
  `citations/<stage>.yml`.
- **Module naming** `<stage>/<verb>_<object>.py`.
- **CLI** (root `cli.py`): `tngxmm <stage> ...` for the stages, and the
  groups `campaign` (run, truth-sphere, check), `certify`, `data`, `cite`,
  `freeze`, `ledger`, `slurm`, `validation`; `tngxmm --help` lists them.
  The `ml` stage has no command. Views are generated by `tngxmm campaign run`
  and selected by the targets table. `tngxmm viz --mermaid [--check]
  [--stdout]` and `--graphviz PATH` export the pipeline graph; `tngxmm cite
  [--lint] [--list] [--json] [--credits FILE]` works on the citation keys;
  `tngxmm freeze check` is gate Z (`core/freeze.py`).

- **Kedro**: `src/tngxmm/settings.py`, `src/tngxmm/pipeline_registry.py`
  (one pipeline per stage + `__default__`). Nodes are built with
  `tngxmm.cites.stage_node(func, inputs, outputs)`, which sets the node name
  to the function name and the tags to `cite.<key>` (Kedro accepts only
  `[\w.-]+`; `cite:<key>` is invalid). Catalog fragments
  `conf/base/catalog/<stage>.yml` are loaded by Kedro's default `catalog*/**`
  pattern. Parameters `conf/base/parameters/<preset>.yml` are GENERATED
  (`make params`) and each holds one top-level key `campaign_<preset>`
  because Kedro rejects duplicate keys across parameter files; no node reads them
  (nodes call `config.get_preset`).
- **Citations**: the decorator `@cites("key", ...)` is the single source;
  every module ends with `__cites__ = collect_cites(__name__)` or declares
  `__cites__: list[str] = []`; `tngxmm cite --lint` fails on a missing or
  under-declared `__cites__` and, once `citations/*.yml` exist, on unknown
  keys. Keys match `[a-z0-9][a-z0-9_.-]*`.
- **Flowchart**: `tngxmm viz --mermaid` rewrites the fenced block between
  `<!-- pipeline:start -->` and `<!-- pipeline:end -->` in `README.md`;
  `make viz-check` fails when the block is stale.
- **Local CI**: `make check PY=<python>` = ruff (correctness rules) + hygiene
  scan + citation lint + schema tests + `pytest -m "not cluster and not e2e"`.
  pytest markers: `unit`, `e2e`, `cluster`.

## 2. ID scheme (`src/tngxmm/schemas/ids.py`)

| id | format | example | notes |
|---|---|---|---|
| `view_id` | `<campaign>-s<snap:03d>-h<halo_id:07d>-v<view>[-r<k>]` | `v1-s099-h0000123-v0` | canonical id of a mock view, unique across campaigns; `campaign` = preset name; `-r<k>` (k ≥ 1) only when a (halo, projection) is observed again in the same campaign (the replica: K halos per observation) |
| mock `obsid` | fixed width `f'{snap:03d}{halo_id:08d}v{view}'` [+ `r<k>`] (`instrument.obsid_style = 'v4'`) | `09900000123v0` | the snapshot is part of it because halo_id 0 exists at every snapshot; unique only within one campaign tree |
| `obsid` | 10-digit zero-padded STRING | `0123456789` | real XMM ObsID; never an int (`normalise_obsid` = `zfill(10)`) |
| `donor_id` | real `obsid` | `0123456789` | the observation whose exposures, N_H, filter and PN mode a mock view inherits |
| `cluster_id` | `J<HHMMSS.s><±DDMMSS>` [+ `-b`, `-c` on collision] | `J153255.7+302056` | Truncated IAU-style position of the highest-precedence catalogue entry (PSZ2 > ACT DR6 > MCXC > other), assigned ONCE into `obs/catalogue/aliases.csv` and never recomputed (recentring must not rename a cluster); names (PSZ2/ACT/Abell) become aliases |
| `zoom_target_id` | int ≥ 0 | `3859` | one per TNG-Cluster zoom region, from `GroupOrigHaloID`; lookup `splits/zoom_target_ids.csv` (snap, halo_id → zoom_target_id); the split unit (frozen `split_by_zoom_target.csv`, seed 7777) |

Names that map onto these: fit target `name` = `mock_<snap>_<halo>_v<view>`
(the display `name` column of the fit table); campaign view directory
`<root>/<sim>/<snap:03d>/<halo:07d>/view<view>/`; the per-camera files are written as
`P<mock obsid>...` directly.

## 3. Per-camera product contract (`src/tngxmm/schemas/products.py`)

- 30 files per view = 3 cameras × {`IMAGE_`, `EXPMAP`} × 5 bands, gzipped FITS:
  `P<obsid>{PNS003,M1S001,M2S002}{IMAGE_,EXPMAP}{1000,2000,3000,4000,5000}.FTZ`.
  Bands [keV]: 1000 = 0.2–0.5, 2000 = 0.5–1.0, 3000 = 1.0–2.0, 4000 = 2.0–4.5, 5000 = 4.5–12.0
  (the PPS names, `schemas.products.BANDS_KEV_SAS`; the fits read bands 2000–5000 only).
  A camera absent from the donor has no files (10 per simulated camera).
- `IMAGE_`: int32 counts; `EXPMAP`: float32 vignetted exposure [s] at the
  band mean energy, same grid (4″/px, 648²; PPS-like TAN WCS centred on the
  cluster, CRVAL = (150.0, +2.0) for mocks).
- Required header keys on every product: `INSTRUME` (EPN/EMOS1/EMOS2),
  `FILTER`, `EXPOSURE` (camera live time [s]), `EMIN`, `EMAX`, and the TAN
  WCS (`CTYPE1/2`, `CRPIX1/2`, `CRVAL1/2`, `CDELT1/2`).
  Additionally on MOCK products: `VIEW_ID`, `POSANGLE`, `SUBMODE`,
  `TNGXVER` (package version), `SPECHASH`. On every EXPMAP:
  `EXPFIX = 'rot-sign-2026-10-06'`.
- `SUBMODE` per camera: with `instrument.pn_submode_header =
  'per-donor'` every camera's products carry the donor's SAS
  submode of THAT camera: PN from the donor package `pn_submode` (unknown ->
  `PrimeFullWindow`, as its out-of-time fraction), MOS1/MOS2 from
  `submode_mos1`/`submode_mos2` (targets tables -> `core.pool.replica_package`
  -> `instrument_view_kwargs(...)['camera_submodes']` ->
  `run_xmm_simulator(camera_submodes=...)`; values seen: `PrimeFullWindow`,
  `PrimePartialW2`, `PrimePartialW3`, `FastUncompressed`). A MOS camera
  without a donor mode keeps `PrimeFullWindow` with the comment
  `MOS mode not in the donor record: assumed`. Keys `RDWINDOW` (`instrument.readout_windows`:
  `full-frame` | `donor`; also on the merged image) and `WINAREA` (per camera,
  detector area read out [arcmin²]). Under `readout_windows = 'donor'` the
  IMAGE events and the EXPMAP of a camera share the window footprint of its
  SUBMODE (`instrument/readout_windows.py`; geometry and its check against
  the PPS exposure maps in DECISIONS.md, "Readout windows"). Under
  `instrument.active_ccds = 'donor'` every camera images the CCD
  segments its donor had (`instrument/active_ccds.py`, data-package tables
  `donor_active_ccds.csv` and `epic_ccd_maps.fits`), events and EXPMAP alike, the
  readout window on top; per-camera keys `CCDRULE` (`donor`), `CCDLIST` (comma list
  of segments: CCD numbers 1–7 (MOS) / 1–12 (pn) and 14 = the outer stripe of MOS1
  CCD4 blanked on board since 2012-12-11) and `CCDSRC` (`pps-expmap`: measured on the
  donor's PPS exposure map; `date-rule`: the epoch of the permanent MOS1 losses, for a
  donor without a map). Absent under `'mask'` (the packaged 2018 masks).
- SAS-ready products (`instrument.product_bands = 'pps-1-5'`,
  `pn_band1_events = 'single-pixel'`, `sas_headers = 'on'`).  The pn band 1 follows the PPS image selection `PATTERN == 0 && RAWY > 12`
  (header `PATTSEL`, `SINGLEFR`, `RAWYMIN`): the mocks carry no event patterns, so each
  event is kept with the CCF single-pixel fraction FRAC_S/FRAC_SD at its energy and the
  events within 12 rows of the readout node are dropped; the pn QPB of 0.2–0.5 keV keeps the
  single-pixel fraction of the filter-wheel-closed events; the EXPMAP is unchanged (eexpmap
  evaluates neither PATTERN nor RAWY).  Header keywords SAS reads, on every IMAGE and EXPMAP
  (`instrument/sas_headers.py`): `TELESCOP = 'XMM'`, `OBS_MODE`, `DATAMODE = 'IMAGING'`,
  `OBS_ID` / `EXP_ID` / `EXPIDSTR` / `DATE-OBS` of the DONOR exposure (`MOCK = T`; `EXP_ID`
  a numeric string `<obsid><nnn>`), `RA_PNT` / `DEC_PNT` the sky position of the optical axis
  (pixel `OPTAXX/OPTAXY`), `PA_PNT = (POSANGLE + 114.2157) mod 360` (the packaged masks have
  the orientation of obsid 0827340901, `PA_PNT` 114.2157; the roll is counter-clockwise on the
  north-up image; DECISIONS.md, "SAS-ready products"), `ONTIMEnn` (live time of each imaged
  CCD, nn = CCD number), for the pn `FRMTIME` [ms] and `TIMEDEL` [s], and the PPS physical
  sky-coordinate keywords (`REFX/REFY*`, `CTYPEnL`, ... : physical pixel 25921 on the optical
  axis).  Every integer keyword beyond 32 bits (`VIEWSEED`) is a string (the SAS DAL cannot
  parse 64-bit integers); the TAN WCS (cluster at CRPIX) is unchanged.  With
  `instrument.pn_edge_rows = 'drop'` the
  pn events within 12 rows of the readout node (RAWY <= 12) are removed in EVERY band, as the real
  cleaned pn event lists have none (header `PNEDGE`); the EXPMAPs are unchanged, because the PPS
  exposure maps (`eexpmap`, which evaluates neither PATTERN nor RAWY) still expose those rows.
  Source detection (`instrument/sas_detect.py`, Kedro `instrument.run_sas_detection`) builds the
  calibration index file with `cifbuild` at the FIXED analysis date `CCF_ANALYSIS_DATE`
  (the day the Valid CCF set was downloaded; mocks and real data alike; recorded with
  the CCF manifest sha256 in `sas_detect/provenance.json`).
- Merged products per mock view: `image_merged.fits`
  (0.5–2 keV integer counts, 648² at 4″, header `EMSCE001..N` live times,
  `POSANGLE`, `CLUSTX/CLUSTY`, `DITHERX/DITHERY`), `image_merged_cov.fits`
  (coverage), `obs_meta.json` (provenance; the view-table row).
- Intrinsic reference map per view (`sim.tngref_map = 'on'`; `sim/project_tngref_map.py`): `tngref_sb_map.fits`, the TNG-Cluster official
  X-ray map (`postprocessing/projections/gas-xray_lum_<band>kev__2r200_d=r200.<snap>.hdf5`,
  temet `catalog/maps.py:projections`) recomputed for the view. Empty primary HDU
  (common header, `BANDS`) + one lossless GZIP_2 tile-compressed float32 image per band
  of `sim.tngref_map_bands` (`EXTNAME = 'SB_<band>KEV'`: 0.5–5.0 and 0.5–2.0 keV),
  `sim.tngref_map_npix`² (2000²). Values log10 SB [erg/s/kpc², physical kpc], -inf
  where no cell emits; luminosity = temet-exact (temet's table, every cell of
  `sim.lx_reference_gas`: 'fof', the FoF group; 'zoom': the original zoom,
  the official cell set; no gas cut, at their periodic minimum image about GroupPos), rest-frame band ÷ (1+z_snap) (`LUMCONV`). Grid: 4 R200c on a side about the
  central subhalo's `SubhaloPos` (`GroupFirstSub`), depth ±R200c, hsml = 2.5 × cell radius,
  temet's SPH kernel (`temet.util.sphMap.sphMap`, imported lazily by `sim/sph_map.py`; temet = pinned `external/temet`, MIT), cells = those cells within
  3 R200c + 300 kpc + |SubhaloPos − GroupPos| of GroupPos (the same read as the `*_tngref`
  cells; those keep their own clip and values). Axes: view v ↔ official `axes_set[v]`
  = `project_luminosity.SKY_AXES[v]`: v0 [x, y] (los z), v1 [x, z] (los y), v2 [y, z]
  (los x); `NAXIS1` runs along the first axis, `NAXIS2` along the second, both
  increasing (= official `Halo_<id>[:, :, v]` element for element; not the mock-image
  frame). Header: `PROVNCE = 'TEMETEXACT'`, `VIEW_ID`, `EMIN/EMAX`, `NPIX`, `FOVKPC`,
  `DEPTHKPC`, `PIXKPC`, `CENX/Y/Z`, `AXIS1/2`, `LOSAXIS`, `BUNIT`, `TEMETTAB` + `TABSHA`
  (sha256), `CLIPKPC`, `NCELLS`, `HSMLFAC`, `SPECHASH`, linear offset axes
  (`CTYPEi = 'SIM<axis>OFF'`, kpc), `GASSEL` (fof | zoom), `PERIODIC`, `SIMULATN`,
  `SNAPMINI`, `OFFICIAL` (the official file name; `'none'` for the box runs).
  Checked by campaign check C2. Agreement with the official maps: equal for
  the zoom cell set; for FoF equal inside the FoF region (DECISIONS "Generation
  decisions after the node pilot").
- `obs_meta.json` under the observing-conditions rule `nn` (release 1.1.1): `exposure_pn/mos1/mos2_s`, `filter`, `pn_mode`, `nh_1e22` and
  `posangle_deg` are those the instrument was run with (the conditions donor's; `exposure_s` the per-camera live times, jitter included),
  `physics_exposure_*_s` (the physics donor's REAL live times, `donor_package.cameras_real_s`; `donor_package.cameras_s` are the replica's jittered ones), `physics_filter`, `physics_pn_mode`, `physics_nh_1e22` (the absorption of the stored `events_v<k>_abs.h5`) and
  `physics_posangle_deg` those of the physics donor (`donor_package`, `donor_id`), `conditions_obsid` the observation of the products and
  `texp_gen_s` the `exp_time` of the photon list (the longest of `exposure_s`); `conditions` is the record of `conditions.json`.
- Under the per-projection draw (`donors.observing_conditions.per_projection`, release 1.2; set in no preset yet) the
  `donor_package` also holds `conditions_anchors`, `{view: obsid}` for every view of the projection scheme
  (`core.pool.halo_projection_anchors`): the `conditions_anchors` column of the target list when it has one
  (`donors.pair_projections`), else the anchors of all rows of the halo-snapshot (`conditions_anchor_id`, else
  `donor_id`), read before `runtime.exclude_donors` is applied, so an excluded donor or a list cut to some views does
  not change the conditions donor of another view; a map that does not cover the views 0 to n-1 of the scheme is
  refused. The record of `conditions.json` has `method = 'projection'`, `per_projection`, `projection`, `projections`,
  `anchor` and `taken_before` (the conditions donors of the earlier views of the halo-snapshot) and no `replica_k`.
  The draw follows view order: where views share an anchor, a later view draws further from it (on the production
  table, six views on one physics donor: median distance 2.20 at view 0, 2.99 at view 5), and in the pairing view 0 has
  the nearest physics donor. Views of a halo-snapshot without a physics donor (`paired` False) cannot be generated yet
  (release 1.2, E1): `core.pool.replica_package` refuses their rows.
- `obs_meta.json` adds `snap_is_mini`, `snap_absent_fields`,
  `periodic_wrap`, `truth_selection`, `n_wrapped_particles` ({"<ptype>:<selection>": n}).
  Runs under the node memory budget (`core/membudget.py`) add `memory`
  ({rss0_gb, uss0_gb, peak_rss_gb, task_peak_gb, est_*_gb, n_fof, granted_gb,
  budget_wait_s, budget_gb}; the worker's peak RSS up to that view): run
  diagnostics, not a product field (absent without a budget).
- Truth profile per HALO-SNAPSHOT (`sim.truth_profiles = 'on'`; needs `sim.truth_columns`;
  `sim/truth_profile.py`): `<root>/<sim>/<snap:03d>/<halo:07d>/truth_profile.h5`, next to
  the `view<k>/` directories and shared by them (one file per halo-snapshot, ~125 kB;
  written atomically when the halo's truth columns are computed, or backfilled by
  `generate_view.ensure_truth_profile` when every view is cached; under
  `sim.truth_selection_hse = 'sphere'`, REPLACED by the spherical
  truth stage, see the next item). HDF5, `format = 'tngxmm-truth-profile-3'`
  (`mass_grid/{r_kpc,M_msun}` — the particle M(<r) on the 0.05–5 R500c grid behind
  `m500c_particles_msun` and the per-view `m500c_zobs_msun` — and the root attributes
  `summary_json` (the scalar truth summary; `truth_profile.hse_from_truth_profile`
  rebuilds every truth column of any view from it, bit for bit) and `truth_selection`
  (`fof` / `zoom` from the generation, `sphere` from the stage); format 2 trees are
  still read and checked (format 2 has `gas/<phase>/fill`; `rho_gas` and the
  HSE masses follow the root attributes `hse_shell_density` — `filling`: phase mass
  / summed phase-cell volume m/ρ, the density of the gas present; `geometric`: / shell
  volume — and `hse_min_filling` — 0.1: shells whose filling factor
  ΣV_cell/V_shell is lower are omitted (NaN) from every HSE curve; `NaN` = none).
  Grid: `n_shells` = 60 log shells 0.01–3 R500c (catalogue)
  about `GroupPos`, physical kpc, minimum-image distances (`r_kpc` geometric centres,
  `r_edges_kpc`). Datasets (each with `unit` and `definition` attributes):
  `mass/M_{tot,gas,dm,stars,bh,gas_mock}` [Msun] exact particle sums at `r_kpc` and
  (`*_edges`) at `r_edges_kpc` (M_tot = gas + DM + stars + BH of `sim.truth_selection`:
  the generation files the FoF group (beyond ~R200c FoF members only),
  'zoom' the original zoom; after the spherical stage every particle of the sphere);
  `gas/{nonsf,hot,mock}/{rho_gas, fill, ne_vw, ne_med, ne_rms, T_mw, T_sl, T_ew, K_mw,
  K_sl, P_th, n_cells}` (phases: non-SF zoom gas = the headline's cells; non-SF and
  T > 5.5 MK; the mock's emitting cells), units Msun kpc⁻³, cm⁻³, keV, keV cm²,
  keV cm⁻³; `kinetic/{sigma_r2, sigma_t2, beta, vr_mean, P_kin}` (non-SF gas);
  `hse/M_{nonsf,hot,mock}_{mw,sl,ew}` (−kTr/(Gμm_p)(dln ρ_gas/dln r + dln T/dln r),
  μ = 0.59), `hse/M_th_nonsf`, `hse/M_thkin_nonsf`; `native/<estimator>/{r_kpc,M_msun}`
  (every truth-column estimator on its own grid; `barnes21_nosf_fit_mu` is the headline:
  the one fitted Barnes estimator, each cell's own mu; the mu = 0.59
  `barnes21_nosf_fit` is not written; classification of every column in section 4.1); `metallicity/{nonsf,mock}/{Z_ew,Z_fe_ew}`: the
  emission-weighted (n_e n_H V) total metallicity GFM_Metallicity/Z_sun and iron
  X_Fe/X_Fe,sun per shell in solar units of the fit's abundance table (root attributes
  `metallicity_abund_table` = `lodd`, `metallicity_z_sun`, `metallicity_xfe_sun`;
  their R500c summaries are `z_ew_r500c_{nonsf,mock}`, `z_fe_ew_r500c_{nonsf,mock}` in
  `summary_json`; NaN without `GFM_Metals`/`GFM_Metallicity`). Root attributes: `snap`, `halo_id`, `sim`, `campaign`, `z_snap`, `h`, `om0`,
  `R500c_kpc`, `M500c_msun`, `R200c_kpc`, `M200c_msun`, `m500c_particles_msun`,
  `centre_ckpc_h`, `centre_kpc`, `centre_definition`, `periodic`, `particle_selection`,
  `source_type`, `mock_selection`, `mock_t_min_k`, `mock_clip_radius_kpc`,
  `hse_headline`, `spec_hash`, `git_hash`, `git_dirty`, `package_version`, `created_utc`,
  `runtime_hse_s`, `truth_selection`, `snap_is_mini`, `snap_absent_fields` (comma list),
  `hse_shell_density`, `hse_min_filling`. Checked by campaign check C2 (`check_truth_profile_file`:
  keys, shapes, halo, M_tot monotonic, M_tot(<R500c) within 5 % of M500c). Read by
  `massfit.render_fit_v4` (true curves on the n_e, T and M(<r) panels).
- Spherical hydrostatic truth (`sim.truth_selection_hse = 'sphere'`;
  `sim/truth_sphere.py`, `python -m tngxmm.core.runner campaign truth-sphere`
  (`--truth-mode auto|memory|streamed`: streamed = `sim/compute_hse_stream.py`, chunked reads
  and per-shell sums, the same truth with a memory independent of the sphere; auto streams a
  sphere above 3e8 particles),
  `slurm/truth_sphere.sh`, run AFTER the generation; in Kedro inside `generate_views`
  after each run's pool). The truth (every HSE estimator column, `m500c_hse_msun`,
  `hse_crossing`, the particle M500, the truth-profile curves) from ALL particles within
  `r_cut = max(sim.truth_sphere_r200c × R200c, 1.02 max(3.15 R500c, 2 R200c))` of
  `GroupPos` (minimum image; `truth_sphere_r200c = 3`): every FoF group and the fuzz
  of a periodic box, the original zoom of TNG-Cluster (other zooms never mixed in). The
  `*_mock` estimators keep the mock's cells (the FoF members inside the sphere with loader fof, the whole sphere with the production loader cutout); photons,
  maps and `*_tngref` are unchanged (FoF). Products: (1) per snapshot
  `<tree>/truth_cutouts/<sim>/snap_<snap:03d>.h5`, `format = 'tngxmm-truth-cutouts-1'`:
  root attributes `sim`, `snap`, `source`, `selection = 'sphere'`, `box_ckpc_h`, `h`, `a`,
  `z`, `n_chunks`, `r_cut_definition`, `truth_sphere_r200c`, `index_definition`,
  `created_utc`; one group `halo_<id>` per halo (attributes `halo_id`, `centre_ckpc_h`,
  `r_cut_ckpc_h`, `r_cut_kpc`, `rmax_kpc`, `r500c_kpc`, `r200c_kpc`, `selection`,
  `sphere_source` = `box-stream` / `zoom` / `cutout`, `sphere_complete`, and for a zoom
  `sphere_lowres_{n_rcut,n_rmax,rmin_kpc,mass_rcut_msun}`, `sphere_contaminated`) with
  `PartType{0,1,4,5}/gidx_delta` (the sorted int64 global snapshot indices delta-encoded,
  gidx = cumsum(gidx_delta), gzip + shuffle; attributes `count`, `sha256` of gidx,
  `encoding`): the snapshot pass is done once, the truth can be recomputed from these rows
  alone. (2) each halo's `truth_profile.h5` rewritten with `truth_selection = 'sphere'`,
  `particle_selection` = the sphere's description, and `sphere_stage_version`,
  `sphere_r_cut_kpc`, `sphere_rmax_kpc`, `sphere_r200c_factor`, `sphere_mode`
  (`stream`/`cutouts`), `sphere_truth_mode = 'streamed'` (only when the truth was computed
  by `compute_hse_stream` from chunked reads: absent from an in-memory file; no
  other field, shape or unit changes, a streamed file is read by every consumer as before),
  `sphere_cutouts`, `sphere_count_pt{0,1,4,5}`,
  `sphere_fill_nonsf_r500c`, `sphere_fill_hot_r500c` (≈ 1: sanity of a full sphere) and
  the cutout attributes above. (3) the results CSVs: the truth columns of every `ok` row
  rewritten from (2) with the row's `z_obs` (values only, no column added, CRLF kept;
  first original kept as `<csv>.pre_sphere_truth.bak`); `obs_meta.json` the same, plus
  `hse_truth_selection = 'sphere'`, `hse_truth_spec_hash`. (4)
  `<tree>/truth_cutouts/<sim>/snap_<snap:03d>.report.json` (timings, throughput,
  memory, per-halo results). Checked by campaign check C17.

## 4. Schemas (`src/tngxmm/schemas/`)

### Intrinsic hydrostatic truth columns

ONE methodological line. The headline `m500c_hse_msun` is the estimator `barnes21_nosf_fit_mu`
(`sim.hse_pressure = 'thermal-fit-mu'`): Barnes et al. (2021, MNRAS 506, 2533) secs. 2.1.5 and
2.4 -- 50 linear shells over 0-1.5 R500c, the shell gas density and the shell mass-weighted
quantity fitted with the Vikhlinin et al. (2006) forms and differentiated analytically -- with
ONE deviation of ours: Barnes et al. state no gas cut for the 3-D profiles (their cuts belong to the synthetic
images), we exclude the star-forming cells (their temperature is the effective equation-of-state value of the
TNG star-formation model) -- with the thermal pressure of each cell as simulated: the
mass-weighted `<T/mu>` with each cell's own mean molecular weight `mu = 4 / (1 + 3 X_H + 4 X_H x_e)`
replaces the temperature and the fixed `mu = 0.59`. The mass is
`M(<r) = -(k r / (G m_p)) <T/mu> (dln rho/dln r + dln <T/mu>/dln r)`; `M500c,HSE` is read at the
INNERMOST downward crossing of `M(<r) / (4/3 pi r^3) = 500 rho_c(z_snap)` beyond 0.4 R500c
(`hse_crossing` counts the crossings; `fit-failed` when the Vikhlinin fits did not converge).
The shell density is the density of the gas present (`hse_shell_density = 'filling'`, shells
filled below 10 % omitted); the particles are those within a sphere about the halo centre (the
spherical truth stage). The same estimator with the assumed `mu = 0.59`
(`barnes21_nosf_fit`) is not emitted (no column, no truth-profile dataset; the code is
behind `compute_hse_truth(mu059_fit=True)` for one unit test). The finite-difference twin without
star-forming gas (`barnes21_nosf`, mu = 0.59) is not emitted either (no column, no
truth-profile dataset, not a selectable headline; behind `compute_hse_truth(nosf_fd=True)`, default
off, for unit tests only).

Sentence for a paper: *"The intrinsic hydrostatic mass of each simulated cluster follows
Barnes et al. (2021): from the shell gas density and the mass-weighted temperature-to-mean-
molecular-weight ratio in 50 linear radial shells out to
1.5 R500c, fitted with the Vikhlinin et al. (2006) parametrisations and differentiated
analytically, using the thermal pressure of each gas cell as simulated (its own mean molecular
weight, not an assumed mu = 0.59). Unlike Barnes et al., who apply no gas cut to the three-dimensional
profiles, we exclude star-forming gas cells, whose temperature is the effective equation-of-state value of
the TNG model rather than a physical one. M500c,HSE is the mass inside the innermost radius beyond
0.4 R500c at which the mean enclosed density falls to 500 times the critical density of the
snapshot."*

All 67 truth columns (`compute_hse_mass.TRUTH_COLUMNS`), classified. Each estimator `<k>` has the
three columns `m500_hse_<slug>_msun` (self-consistent M500 at 500 rho_c(z_snap)),
`mhse_<slug>_r500c_over_m500c` (M_HSE(<R500c) / M500c) and `mu_hse_<slug>` (the mu used; NaN: none).

Not emitted: the three `*_barnes21_nosf` columns (`m500_hse_barnes21_nosf_msun`,
`mhse_barnes21_nosf_r500c_over_m500c`, `mu_hse_barnes21_nosf`; the finite-difference, mu = 0.59 estimator
without star-forming gas) and their `native/barnes21_nosf` dataset: too easily mistaken for the headline
`barnes21_nosf_fit_mu`. Confusion hazard (for the paper's tables and for ML targets): every
finite-difference Barnes column (`barnes21`, `_xcut`, `_tsl`, `_mock`) and the 17 `m500_hse_*` columns
share the prefix of the headline's own copy. Use `m500c_hse_msun`; take any other `m500_hse_*` only as a
named diagnostic. The truth-profile files carry `native/<k>/{r_kpc,M_msun}` for the estimators above (neither

Campaign Lx convention (`photometry.lx_bkg = 'masked-clipped'`, campaign check C6): point sources masked in the aperture (ring-filled) and the 1.1–1.6 r
annulus with the hydrostatic fit's source lists (mocks: `pts_sources.fits` above the per-donor
threshold; real data: the PPS point sources), King-PSF mask radii 30–150″, a sector-clipped
annulus mean, and no clipping: `lx_<ap>` is NaN unless `lx_<ap>_flag == 'ok'`, the signed value
is `lx_<ap>_signed`; the masked aperture pixels are filled with the mean of the unmasked pixels
in the same 8″ ring (`lx_<ap>_mask_frac` = masked fraction, `lx_<ap>_area_corr` = corrected /
unmasked net counts; > 50 % masked → flag `masked`). Real observations in the same convention:
`photometry/measure_obs_lx.py::measure_obs_lx_masked` (same columns).

The campaign columns of a mock view are measured inside the TRUE R500c, about the true centre, at
the true T_vir, and, because the view's SAS detection does not exist yet, masked with the
simulated point sources above the donor's threshold (`campaign_lx(source_list='default',
strict=True)`); the real observations' table of `measure_obs_lx` uses the catalogue mass and
position.  The two are not a mock-real pair.  The pair is the fit-target seed photometry below,
the same procedure on both sides (nominal position, guarded peak, iterated first-guess R500, the
image's own SAS list).

`$TNGXMM_DATA/tables/catalogue_positions_v4.csv` (`photometry/catalogue_positions.py`): per real
observation `obsid, catalogue` (psz2 | act_dr6 | other), `entry` (the `cluster_id_entry`),
`ra_cat, dec_cat`, `snr`, `sigma_arcmin` (per-axis Gaussian sigma of the catalogue position),
`r90_arcmin` (its 90 per cent radius: PSZ2 `POS_ERR`; ACT DR6 2.146 x 1.428 / fixed_SNR),
`theta500_sz_arcmin` (PSZ2: the angular R500 of the entry's MSZ, the filter scale of a mock's SZ
position; NaN otherwise), `z_type` (ACT DR6 `redshiftType` spec | phot; a PSZ2 redshift typed from
its counterpart's published entry, photometric, SPT-SZ or ACT DR6, `psz2_redshift`, else `untyped`,
as for the other positions, which publish no type), `z_err` (ACT DR6 `redshiftErr`; a PSZ2
counterpart's `Z_LAMBDA_ERR`, SPT-SZ `e_z`, ACT DR6 `redshiftErr` or its catalogue paper's sigma_z;
NaN where none is published), `z_source` (ACT DR6 `redshiftSource`, PSZ2 `zID`), `z_err_source`
(`catalogue:<name>` or `paper:<name>`) and `z_rule` (the redshift rule, `REDSHIFT_RULE_VERSION` =
3).  The builder reads the counterparts' published redshifts from the CSV of
`tools/psz2_counterpart_redshifts.py` (`--counterparts`) and refuses a PSZ2, ACT DR6 or counterpart
file other than the pinned one (`INPUT_PINS`, recorded in the provenance and checked by the readers).  The nominal
position of a real target, the catalogue error drawn for a mock (keyed by the view's `VIEW_ID`),
the rule of a mock's catalogue position (`position_rule`) and a mock's redshift error
(`mock_redshift`, same key) all come from it; provenance JSON next to it (input catalogues
hashed).  A table without a column, or of another redshift rule, is refused where it is needed.  A mock image carries its catalogue position before the
measurement error, where the drawn error is applied (0-indexed pixels, like `CLUSTX`/`CLUSTY`;
`sim/catalogue_centre.py`, rule version 3): on the map filtered as the donor's catalogue filters
(ACT DR6: the template over the lensed CMB of the Planck 2018 best fit plus 14 uK-arcmin white
noise, the packaged `tngxmm/sim/calibration/cmb_tt_lensed_planck2018.csv`; PSZ2: white noise),
the detection reached from the halo centre by steepest ascent, then the catalogue's estimator
(PSZ2: the peak, merged with any higher maximum within 10 arcmin; ACT DR6: the S/N-weighted
centre of the S/N > 3 segment inside the cylinder, the map scaled so that the halo's own maximum
has the entry's S/N; X-ray: the peak of the 16 arcsec-smoothed emission).  For a PSZ2 or ACT DR6 donor the SZ position is in `SZCENX`,
`SZCENY` with `SZRULE` (the catalogue), `SZTHETA` (filter theta500, arcmin), `SZBEAM` (beam FWHM,
arcmin) and, for ACT DR6, `SZSNR` (the entry's S/N) and `SZNOISE` (the white level of the
filter's noise model, uK arcmin); for a donor of neither catalogue the X-ray
position is in `XRCENX`, `XRCENY` with `XRSMOOTH` (arcsec); both with `CATPOSV` (the rule
version) and `CPFLAG` (`ok`, or, comma-joined, `global-elsewhere` when the highest point of the map
in the cylinder is not part of the detection, `merged` when the detection's highest maximum is not
the one reached from the halo centre (a neighbour within PSZ2's 10 arcmin, or in the same ACT
segment), `off-halo` when the position lies outside the halo's projected R500c, `edge` when the
kernel's support about the position reaches beyond the cylinder).  The photon file holds them as `parameters/sz_centre_deg,
sz_rule, sz_theta500_arcmin, sz_beam_fwhm_arcmin, sz_map_pixel_arcmin, sz_snr,
sz_noise_uk_arcmin` or `xray_centre_deg, xray_smoothing_arcsec, xray_map_pixel_arcmin`, with
`catpos_version, catpos_estimator, catpos_flag, catpos_global_offset_arcsec, catpos_edge_weight,
catpos_saddle_snr`, and
`obs_meta.json` as `catalogue_position` (the rule with its `estimator` and `version`, the scales,
`centre_deg`, `map_pixel_arcmin`, `flag`, `global_offset_arcsec`: position to the highest point
of the map, `edge_weight`: the share of the kernel, in absolute value, about the position beyond
the cylinder, and `saddle_snr`: for a merged ACT segment, the S/N at which the halo's maximum and
the higher one part).  A view without the keys of its donor's rule, or with another rule version,
filter scale, beam, S/N, noise level or X-ray smoothing than the rule of its donor's entry under
the preset (the SZ centroid of release 1.1.3 had none of the keys), is refused by the centre
search and by `build-fit-targets`; a resumed campaign makes such a view again
(`generate_view.cached_position_current`).

Mock fit targets (`massfit/build_fit_targets.py`) record, besides the seed columns, the catalogue
entry the view replicates and the redshift it gives the view: `physics_donor_id, catalogue,
r90_arcmin, position_rule` (`sz:<catalogue>` | `xray`), `position_flag` (the image's `CPFLAG`),
`z_obs` (the photons' redshift), `z_offset` (the drawn error of a photometric catalogue redshift),
`z_type, z_err`; the target's `z` is `z_obs + z_offset`, the redshift of the seed, the centre
search and the fit; `view_dir`; and the offsets `sz_offset_arcsec` (position before the error -
true centre), `catalogue_error_arcsec`, `move_arcsec` (centre found - nominal position).  The fit
passes `z_obs`, `z_offset`, `z_type` of a targets row to `result.json`, whose `z` is the fit's,
and refuses a photometric catalogue redshift without `z_obs`; the truth tables
(`analysis/tables.py::mock_table`, `render-fit-v4`) take a mock's truth at `z_obs`.
`fit-hydrostatic --resume` keeps a finished fit only when its `z`, `z_obs` and the
`image_tree_sha256` of its provenance match the job.  The closure records (`closure.json`) keep
the same entry columns, the offsets, `z_fit` and `catalogue_position_version`; a record of another
rule version, or whose `z_fit` is not the current draw for the cell, is fitted again, and `collect`,
`closure_table` and the certify queue (done test `closure_fit_done`) treat it as `stale`, never
as a result.  A generated cell whose `truth.json` holds another rule is generated again
(`generate --check-only` lists such cells; a rerun on linked views, `GEN_FROM`, stops on them).  `python -m tngxmm.validation.catalogue_moves --mock
<targets.csv>` reports the moves of mocks and real targets per catalogue (fractions beyond r90 and
2 r90, median in r90 units, bootstrap intervals over clusters; mocks per view and per physics donor)
and applies no threshold.

Fit Lx seeds (`massfit.seed_lx_photometry = 'campaign'`): `lx_0p35mpc`,

### 4.9 Canonical datasets (`src/tngxmm/ingest/schema.py`, format `tngxmm-canonical-1`)

What the `ingest` stage writes for every simulation and the later stages read (DECISIONS, "Multi-simulation
pipeline").

* **Simulation descriptor** (`src/tngxmm/ingest/descriptors/<name>.yml`, `ingest.descriptor`): name, family
  (`tng` | `swift`), base path, zoom or box, box size, cosmology, hydro scheme, snapshots with their redshifts,
  halo catalogue and mass definitions, the canonical field mapping with its conversions, temperature,
  ionisation, star-forming, wind and net-heating rules, metallicity source and element list, citations, status
  (`production` | `validation`).  Shipped: `tng-cluster`, `tng300`, `tng100`, `tng50`, `simba`, `eagle`,
  `flamingo`.  A preset that sets `sim.source` carries `sim.descriptor_sha256` (sha256 of the parsed file) in
  its canonical JSON.
* **Halo table** (`schema.HALO_COLUMNS`; `tngxmm ingest halos` for the TNG family): sim, snap, z, halo_id, host_id, centre (physical kpc, potential
  minimum), M500c, R500c, M200c, R200c, gas particles inside R500c, primary flag.
* **Cube index files** (production route of the TNG family, `runtime.cube_store = 'index'`): the global snapshot
  indices of each halo's cube, format `tngxmm-mock-cutouts-1` (`<tree>/mock_cutouts/<sim>/snap_<snap>.h5`, written by
  `campaign mock-cutout`); the reader converts the cells to the canonical gas below in memory
  (`ingest.tng.canonical_gas`, `sim.emission.GasCells`) and nothing else is stored.
* **Materialised gas cubes** (FLAMINGO, fixtures and tests; `<cube_root>/<sim>/cubes_<snap:03d>.h5` +
  `.manifest.json`, `ingest.cube_io`): per halo
  group `halo_<id>` with the subgroups `gas`, `dm`, `stars`, `bh`, `lowres_dm`; every particle inside the
  axis-aligned cube of half-side `half_side_r500c` R500c about the centre (per-axis minimum image).  Gas fields
  (`schema.GAS_FIELDS`): `pos_kpc` f8 (N, 3) absolute physical position at the minimum image about the centre,
  `vel_kms` f4 (N, 3) peculiar, `mass_msun` f8, `rho_gcm3` f8, `u_kms2` f4, `T_K` f4, `x_e` f4 (n_e / n_H),
  `Z` f4 (the descriptor's total metallicity), `X_el` f4 (N, n_el) with the group attribute `elements`
  (H first; the last column `other` is the metal mass in no tracked element), `sfr_msun_yr` f4, `flags` u1
  (bit 0 star forming, 1 wind, 2 net heating, 3 coarse), `ids` u8; optional `Z_particle`, `cooling_rate`,
  `hsml_kpc`.  Other kinds: `pos_kpc` f8 and `mass_msun` f8 (or the halo attribute `<kind>_mass_msun_const`).
  Halo attributes: `centre_kpc`, `r500c_kpc`, `m500c_msun`, `r200c_kpc`, `m200c_msun`, `half_side_r500c`,
  `half_side_kpc`, `complete` (a reader refuses false), optional `complete_within_kpc`, `bulk_vel_kms`,
  `cutout_report_json`; TNG family also `catalog/group/*`, `catalog/subhalo/*` (native rows, native dtypes) and
  the file group `native_header`.  File attributes: `format`, `schema_version`, `sim`, `snap`, `z`, `a`, `h`,
  `msun_in_g` (the simulation's own solar mass), `family`, `box_size_ckpc_h` (SWIFT).  Every dataset is gzip 4
  with shuffle and carries `sha256` (of its C-order bytes), `unit` and `doc`.
* **Reading** (`ingest.canonical_source.CanonicalHaloSource`): the HaloSource protocol of
  `sim.read_halo_source` over a cube file; `gas_cells()` returns the gas as `sim.emission.GasCells` without
  any arithmetic.  `runtime.cube_store = 'canonical'` and `runtime.cube_root` (or `campaign run --cube-root`,
  environment `TNGXMM_CUBE_STORE` / `TNGXMM_CUBE_ROOT`) make the generation read the cubes; the two runtime
  fields are not hashed because the TNG products are the same bytes either way.

## 5. CampaignSpec presets (`src/tngxmm/config.py`)

`CampaignSpec` has sections `cosmology`, `constants`, `sim`, `donors`,
`instrument`, `photometry`, `massfit`, `runtime` and a top-level
`seed_offset`; each field records its value, unit, the module that reads it
(`reads`), a citation key and a one-line description
(`python -m tngxmm.config --show v1`). The field defaults ARE the `v1` values:
`CampaignSpec()` is the `v1` physics.

One preset family (`config.PRESETS`):

| preset | what |
|---|---|
| `v1` | TNG-Cluster: every primary zoom target with M500c >= 1e14 Msun at the full snapshots 99, 91, 84, 78, 72, 67, 59, 50, 40, three projections each, K = 5 replica views per reference observation (`config.PRODUCTION_PRESET`) |
| `v1_tng300` | the same physics on the periodic box TNG300-1 (every FoF central) |
| `v1_tng100`, `v1_tng50` | TNG100-1 and TNG50-1 (held-out resolution) |

The box presets change only `sim.sim_name`, `sim.base_path`, `sim.primary_only` and the
random-stream key. `sim.rng_campaign` is that key, a string (`v4`, `v4_tng300`, `v4_tng100`,
`v4_tng50`): the name of the committed target-list family (`campaigns/v4*`), so that a view pairs
with the view of the same (snapshot, halo, projection) generated under that key. It is not a preset
name. `tngxmm donors replica --preset v1` writes `targets_v4.csv`.

Release 1.2 pairs halo-snapshots, not views (`donors.pair_projections.pair_projections`, not yet wired into a
command; the two mass columns have no default): one row per halo-snapshot and projection with `paired`, `donor_id`
(the physics donor; empty when unpaired), `conditions_anchor_id`, `conditions_anchors` (the anchors of every view of
the halo-snapshot, `"0:<obsid>;1:<obsid>;..."`), `donor_rank`, `donor_repeat`, `n_candidates`, `n_physics_donors` and
`shortfall`. The `paired` flag is read by one rule (`pair_projections.paired_value`: a boolean, `true` / `false` in
any case, or 1 / 0; anything else raises). A view table with a `paired` column is read by every mock-against-real
statistic through `pair_projections.drop_unpaired` (gate P, the matched draw, the replica's mass-match check, the
realism split and selection); a table without it pairs every row. Generating the views of an unpaired halo-snapshot is
not supported yet (E1).

Every field is read by some code outside `config.py`
(`test_every_hashed_field_is_read_by_some_code`).

Fields of the multi-simulation pipeline, hashed only when set; `sim.emission_abundances` ('full') and
`sim.emission_untracked` ('other-solar') are set in every preset since 2026-10-28 (the hashes of all presets but
v1_common changed; DECISIONS, "Emission abundances"):
`sim.source` (the simulation descriptor; when set, `sim.descriptor_sha256` joins the canonical JSON),
`sim.emission_abundances` (`full` | `common`; unset = the legacy emission of release 1.1) and
`sim.emission_untracked` (`other-solar` | `fe`), `sim.photon_spread` (`sph-kernel`; unset = uniform in the cell's
volume-equivalent sphere), `sim.cell_resample_msun` (a diagnostic arm: the cells degraded to particles of that mass,
`sim.emission.resample_cells`; unset = every cell).  Runtime (never hashed): `runtime.cube_store`
(`index` | `canonical`) and `runtime.cube_root`.

**Hash**: `spec_hash()` = sha256 of the sorted-key compact JSON of every
field except the `runtime` section and the free-text `description`
(first 16 hex digits in tables; `spec_hash(64)` for the full digest), together with the sha256 of the package's
calibration tables (`config.calibration_tables_sha256`), the digest of the columns of its observation table
`obs/catalogue/observations.csv` that the stages read (`config.observation_tables_sha256`; the list is
`config.OBSERVATION_COLUMNS`: identity, position, redshift, Galactic column, exposures, filters, modes, pointing,
epoch, matching mass, recorded reference mass, sample flags; rows in obsid order, numbers as their shortest
round-trip text, so the order of rows and columns, the number of digits and every other column do not enter) and of the data
manifest `sim/data_manifest.csv` (`config.data_manifest_sha256`: the pinned sha256 of the APEC, ECF and reddening
tables of the data package and of the AtomDB files of the photon spectra, `sim.data_inputs`).
`generation_hash()` also leaves out the `massfit` section: it determines the
generated products. Current values (generated by `python -m tngxmm.config --write-docs docs/dev/INTERFACES.md`
and checked by `tests/unit/test_config.py::test_interfaces_hash_block_is_current`, so

## 6. RNG contract (`src/tngxmm/core/rng.py`)

- One scheme, `sha256-v1`: every random draw of a view comes from an independent stream seeded
  from the view's coordinates. The seed is the first 8 bytes (big-endian) of the SHA-256 of
  `'{namespace}|rng|sha256-v1|{campaign}|{sim}|snap={snap:03d}|halo={halo_id}|view={view}|real={realisation}|{purpose}|{camera or "-"}'`,
  masked to 63 bits. `campaign` is the stream key `sim.rng_campaign` (else the preset name);
  `realisation` 0 is the production draw and `k >= 1` a re-observation of the same view
  (the instrument replay); `namespace` is `tngxmm`.
- Closed vocabulary of purposes. View level: `z_obs`, `donor`, `photon_counts`, `photon_energy`,
  `photon_position`, `absorption`, `posangle`, `dither`, `partition`, `agn_sky`, `global_legacy`
  (seeds the global numpy stream for library code that draws from it), `conditions` (the conditions-donor
  draw and its jitter, instrument.conditions_donor; only drawn under that switch). Donor level
  (`seed_for_donor`, `'{namespace}|rng|sha256-v1|{campaign}|donor={obsid}|{purpose}'`): `conditions` (the
  permutation of a donor's conditions candidates shared by its replicas). Per camera (MOS1, MOS2, PN):
  `psf`, `rmf`, `background_sky`, `agn_counts`, `oot`, `background_qpb`. An unknown purpose, or a
  camera on a view-level purpose, raises.
- Under the per-projection conditions draw (release 1.2) the conditions donor of view v depends on the
  first integer of the `conditions` stream of every earlier view of the same halo-snapshot (same key,
  simulation, realisation and scheme; `conditions_donor.sibling_conditions_rng`). No stream or purpose is added and
  the view's own `conditions` stream is used as before: one integer for the candidate, then the jitter. With a
  single candidate numpy draws nothing for the range of one, and the jitter starts at the stream's first number
  (under the release 1.1.1 draw as well).
- `ViewStreams` is what the per-view generation and the instrument stage receive: one cached
  `numpy.random.default_rng(seed_for(...))` (PCG64) per (purpose, camera). `fingerprint()` hashes the
  final state of every stream, a cheap draw-order check; `provenance()` records the scheme, the
  stream key, the realisation and the fingerprint in `obs_meta.json`.
- The call order and the conditional skips of every draw are part of the contract: a changed draw
  order changes every product. Known-answer seeds and the fingerprint of a view are unit-tested.
- `SPLIT_SEED = 7777` is the frozen seed of the train/val/test split by zoom target.

## 7. Roots (`src/tngxmm/core/paths.py`)

| variable | meaning | Vera value |
|---|---|---|
| `TNGXMM_DATA` | the data package (assets `tables`, `embeddings`, `mosaics-1`, `mosaics-2`, `obs`, `fits`, `fixtures`, one directory each) | default `<repo>/data` |
| `TNGXMM_FIXTURES` | fixture cutouts and golden outputs, never in git | `$TNGXMM_FIXTURES` |
| `TNGXMM_DEV` | dev scratch root; a workstream `<id>` works only under `$TNGXMM_DEV/<id>/` | `$TNGXMM_DEV` |
| `TNGXMM_PROD` | production root (campaign trees, fit work dirs), set only by the runner | set by the runner |

- mbproj2d responses and rate caches live under `/vera/ptmp` (apptainer bind
  mounts; `mbproj_apec._check_tables` raises otherwise). Each dev workstream uses
  its own `rate_cache_dir(<id>)` = `$TNGXMM_DEV/<id>/mbproj2d_cache`;
  production uses `$TNGXMM_PROD/mbproj2d_cache`. Never shared: a killed lock
  holder hangs every fit that waits for it.
- Temporary files never go to `/tmp`: `TMPDIR`, `PIP_CACHE_DIR`, `HF_HOME`,
  `MPLCONFIGDIR`, `XDG_CACHE_HOME` point into `$TNGXMM_DEV/<id>/`
  (environment/bootstrap.sh). pytest: `pyproject.toml` sets
  `--basetemp=$TNGXMM_DEV/pytest`; `make` overrides it
  per workstream (`$TNGXMM_DEV/<WS>/pytest`) because pytest wipes the basetemp
  at start and parallel sessions would delete each other's files.

## 8. Fixtures (`tests/fixtures/README.md`)

- Root `$TNGXMM_FIXTURES` = `$TNGXMM_FIXTURES/`, with `manifest.json`
  (sha256 per file); `tests/fixtures/check_fixtures.py` validates it. Never in git; shipped as the
  `fixtures` asset of the data package.
- TNG cutouts: `tng/099_19327357.hdf5` (snap 99, z = 0, zoom_target_id 3859, M500c 1.533e14,
  R500c 831.5 kpc) and `tng/067_19542651.hdf5` (snap 67, z = 0.503, zoom_target_id 2195, M500c
  1.518e14, R500c 689.1 kpc), cut at 5 R500c in the TNG public-API cutout layout: `Header` (all
  snapshot header attributes; file counts in `NumPart_*`, snapshot totals kept separately), `Group`
  (all 32 group-catalogue fields), `Subhalo` (53 fields of the central), PartType0/1/2/4/5 with native
  names, dtypes, units and snapshot order, plus a uint8 `InFoF` per type (`InFoF == 1` reproduces
  `loadHalo` exactly, IDs and order verified). Total particle mass inside R500c = catalogue M500c to
  1.00002.
- Observed products: `obs/0551830101/` (Abell 1835) and `obs/0551780401/` (Abell 2029), PPS bands
  1-5 for PN/MOS1/MOS2 plus exposure maps, the EPIC band-8 image and the two project mosaics
  (labelled non-XSA).
- Temet reference: `tests/e2e/golden/temet_reference.npz` (temet's own X-ray output on the fixture
  halos, made by `tests/fixtures/make_temet_reference.py`).
- `golden_v1`: the products of `campaign run --preset v1 --snap 67` on the cutout of halo 19542651,
  `campaign truth-sphere` and `campaign check`, and the quick fits, made by `tools/make_v1_golden.sh`
  on a node.
- `HaloSource` (`schemas/signatures.py`) reads snapshot and cutout alike; the gas loader
  (`loader='fof'`) is bit-identical from both sources.
- The acceptance of the Kedro pipelines is that, on the fixture halo with preset `v1`, a Kedro run
  writes what the CLI writes (`docs/dev/KEDRO.md`).

## 9. Bank format

- Canonical stored science artefact: the merged 0.5-2 keV mosaic as uint16
  counts (+ gzip, ~66 KB), full 648² frame, in the `mosaics` assets of the data package.
- The bank render (inferno RGB, `normalize_image` stretch, 640² native crop)
  is DERIVED deterministically from the mosaic by `tngxmm bank render`; it is
  what DINOv3 consumes and it is not shipped.
- The render PNG bytes and the embedding vectors of the frozen bank entries are the reference of the
  bank tests.

## 10. Working rules for shared files

- The shared files are `core/`, `config.py`, `schemas/`, `pyproject.toml`, the root `cli.py`,
  `.githooks/` and `.gitignore`. A change to one of them is a change of the contract: it is
  made once, with its tests, and announced in `CHANGELOG.md`.

## 11. Environments (`environment/README.md`)

- Three pinned lock files: `environment/sim.lock.txt` (python 3.10.9, numpy 1.26.4, pyxsim 4.4.2,
  soxs 4.8.5, yt, xmm_simulator 0.2.0 @ upstream 9fdedb4e + `environment/patches/` for the scipy
  `interp2d` removal and the MOS QE NaN fix; the stale upstream `build/lib` is removed before the
  build), `massfit.lock.txt` (numpy 2.2.6, mbproj2d 0.2 @ ff497101, pyfftw, nlopt, emcee; GCC
  12.1.0; HEASoft 6.35.1 apptainer image) and `embed.lock.txt` (72 packages layered on the
  anaconda module's 317; torch 2.5.1+cu121, transformers 4.57.3). Random draws are identical under
  numpy 1.26.4 and 2.2.6, so the split exists for dependency pins, not for reproducibility.
- `environment/bootstrap.sh` builds the shared environments under
  `$TNGXMM_SITE_PTMP/tngxmm_env/{sim,massfit,embed}` (idempotent; `--dry-run` resolves
  everything).
- Thin per-worktree venv: `environment/thin_venv.sh <shared-env> <worktree> [<id>] [--with-kedro]`:
  a `.pth` file adds the shared env's site-packages and the user site is disabled
  (`--system-site-packages` only for embed, module torch). `environment/runtime_env.sh` sets
  TMPDIR, PIP_CACHE_DIR, MPLCONFIGDIR, XDG_CACHE_HOME (soxs data symlinked back to
  `~/.cache/soxs`), HF_HOME/TORCH_HOME (the gated DINOv3 cache), ATOMDB (must be set BEFORE
  `import xmm_simulator`), CCF_PATH, MBPROJ_* and the apptainer PATH.
- XSPEC: `environment/check_xspec.sh` prints `RESULT: XSPEC OK`; XSPEC 12.15.0; the image's default
  APEC 3.0.9 gives NaN at kT 7.9-8.1 keV, the 3.1.3 tables at `MBPROJ_APECROOT` are finite;
  `/vera/ptmp` is visible inside the container, `/vera/u` is not.
- Login-node etiquette: at most 4 cores, `OMP_NUM_THREADS=1`, fixtures only.
