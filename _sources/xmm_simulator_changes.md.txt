# Changes to xmm_simulator

The instrument stage builds on [xmm_simulator](https://github.com/domeckert/xmm_simulator) 0.2.0 (D. Eckert), pinned
at commit [`9fdedb4e`](https://github.com/domeckert/xmm_simulator/tree/9fdedb4e8c6375a0be18e1307c12d9dc63fc6fb5).
This page lists every way the v1 stage (`conf/base/parameters/v1.yml`, block `instrument`) differs from running that
commit as shipped. It is the source for the paper's description of the instrument model.

**In short.** Two lines of upstream source are patched (U1, U2). The event loop is re-implemented in `tngxmm.instrument`.
The re-implementation reuses upstream's calibration-file selection, packaged masks, RMFs and FWC spectra, sky-model
constants and AGN template, and `calc_arf` when `arf_model` is unset (the presets fold the fit's effective area, F8).
Everything else is an addition, listed below with its switch and source.

## How to maintain this page

* One row per change, under a stable ID (U, F, R, C, B, S, P). Edit rows in place; never append a change log.
* A change that is undone moves to **Retired** with the date and commit. Its ID is not reused.
* **Upstream** links point into the pinned commit, so the line numbers do not drift. **Ours** names a module and
  symbol, not a line.
* `tests/unit/test_xmm_simulator_changes.py` checks:
  * every **Ours** symbol exists;
  * every `switch: value` matches `v1.yml`;
  * every realism switch of `InstrumentOptions` appears on this page.

  A new switch fails the test until it has a row here.
* **Status**: `v1` is in the v1 preset on `main`; `branch <name>` is not merged yet. **Open** points to the list at
  the end.

Upstream base URL below: `U` = `https://github.com/domeckert/xmm_simulator/blob/9fdedb4e8c6375a0be18e1307c12d9dc63fc6fb5/xmm_simulator/`.

## Open

* **O1** A number with no published source: 15 keV grid (F3), 4×4 sub-samples (R3), footprint level radius 8′ and floor
  0.5 (C4), live time as the 95th percentile within 1.5′ (C5), anomalous-CCD thresholds 5σ and 0.25 (S5). The pn readout
  tilt (B10) and the placement of the FWC and soft-proton detector maps (S2) come from SAS's own DET → sky solution of
  the observation behind the packaged masks since 2026-11-03 (`donor_background.DET_TO_MASK`, `tools/det_to_mask.py`).
* **O2** Closed 2026-11-03: the AGN redshift, N_H and photon index come from the Ueda et al. (2014) population at each source's soft flux (`agn_population: ueda14`); the N_H cap 22, calibrated against Moretti's hard-band counts, stays only in the earlier draw.
* **O3** The claim that R1 matches upstream statistically rests on one A/B ratio (1.0044) recorded in a legacy document.
  Rerun `run_xmm_simulator.run_upstream_reference` on one view before the paper says so.
* **O4** `pattern_loss_factor: 0.92` was read only as a switch and never multiplied in. Done (2026-11-03): the field is
  now the switch `pattern_loss = 'ccf'`.
* **O5** Chosen to reproduce the donors' PPS maps rather than taken from a calibration: B6, B8.
* **O6** Condition-space weights 9/9/4 and n = 5 are design choices (C7).
* **O7** The Leccardi & Molendi spectral shape was fitted to MOS data over 0.7–10 keV and is used over 0.5–12 keV and for
  the pn (S3, S4). With S4 the pn background matches real data to ±0.03 dex at 1–12 keV, but 0.2–0.5 keV is 0.05–0.07 dex high.
* **O8** The sky model takes each donor field's own LHB and halo levels from its RASS spectrum since 2026-11-03 (S8);
  the check against the donors' own XMM soft-band field (STATUS A2) is still to run (ledger `instrument.sky_background`).
* **O9** Upstream's CCF selection takes the highest issue number in each file name, not the constituent valid at a
  date. For the MOS quantum efficiency that is EMOS1_QUANTUMEF_0026 and EMOS2_QUANTUMEF_0024, files of 2002 whose
  header issue is 14 and which SAS no longer selects (it takes 0020 before 2002-11-08 and 0021 after): the MOS on-axis
  area is 6.4 / 2.9 per cent lower at 0.5-1 keV and 2.0 / 1.7 per cent lower at 1-2 keV than with the issues SAS uses.
  Alone it moves the temperature of a real observation fitted with the shared ARFs by -4.9 / -6.5 / -9.1 per cent
  (MOS1), -2.3 / -3.3 / -4.8 (MOS2) and -1.2 / -1.7 / -2.4 (three cameras) at 3 / 5 / 8 keV, about the size of the
  EPIC-to-NuSTAR term with the opposite sign. The shared fit ARFs (`massfit.build_responses`) use the same rule, so
  mocks are generated and fitted alike; a real MOS fit is not. B14 (`ccf_selection: valid-at-date`, generator and fit
  together) follows SAS; with the shared responses the real-side error of the three cameras is then +2.2 / +3.9 / +6.7
  per cent instead of +1.0 / +2.2 / +4.1 (median of 13 epochs). B12 with `massfit.responses: per-observation`
  removes the response terms (ledger `instrument.response`); the presets use B12 and B14 since the author's
  adoption of 2026-11-04.
