tngxmm¶

Mock XMM-Newton EPIC observations of simulated galaxy clusters (TNG-Cluster, TNG300, TNG100 and TNG50 of IllustrisTNG; FLAMINGO; SIMBA and EAGLE as validation runs), each observed under the conditions of a real archival XMM observation, with the same aperture photometry, source masking and hydrostatic-mass fit applied to the mocks and to the real observations. The aim is to measure the bias of X-ray hydrostatic masses on simulated clusters, and to test whether the mocks are close enough to real data for that bias to transfer.

Status: the pipeline and its provenance are in place; the science validation is not. The mass fit is about 15 per cent low on idealised clusters once a realistic background is present, and a classifier still separates mocks from real observations; the pre-registered realism evaluation has not been run. The freeze of the configuration is judged on a pilot of 60 real and 60 mock fits (November 2026); on its mocks the fit lies above the simulation’s own hydrostatic mass, and the cause is not established. Pass 1 of the pairing on the fitted mass (one view of each of 5,001 FLAMINGO L1_m8 halo-snapshots) is generated and fitted with short chains; the pass-2 list with the 170 added observations is not built yet. Details on the documentation page “Validation status” (docs/validation.md).

Documentation¶

The Sphinx site in docs/ (make docs) holds the overview, the science definitions, the validation status, the configuration with every spec field and its citation, the assumption ledger, and one page per Kedro pipeline generated from the registry. Running each stage: docs/PIPELINE.md. One production run from its target list to its fitted masses: docs/production.md; what to do when a job stops: docs/when-a-run-stops.md. Version history: CHANGELOG.md.

Pipeline¶

ingest (each simulation into canonical gas cells and halo tables) -> obs (the 808 real observations: the bank of 638 and the 170 added on 2026-11-25) -> donors (which halo is observed as which observation) -> sim (photons, instrument, photometry and truth per view, inside the node sim.generate_views; instrument and photometry collect and measure its products) -> massfit (hydrostatic M500) -> viz; bank -> embed (image bank, DINOv3 embeddings). Outside the default run: validation (closure grid), analysis, certify, donor_tables, realism, setup (the downloads of a machine away from the cluster). The ml stage is not implemented.

Install and run¶

python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"            # importing tngxmm needs only click
tngxmm --help
python -m tngxmm.config --show v1  # the production preset: every field with value, unit, reader and citation

The scientific stacks (simulation and instrument, mass fitting with XSPEC, embeddings) are pinned in environment/; Kedro is an overlay of one of them (environment/thin_venv.sh <sim|massfit|embed> . <id> --with-kedro). Each stage is a Kedro pipeline whose nodes call the same functions as the tngxmm <stage> commands and the SLURM jobs, so both routes write the same bytes:

kedro run --pipeline donors                         # re-draw the committed target lists in place
kedro run --pipeline sim --params sim.snaps=[67]    # one snapshot of preset v1
kedro run --env fixtures --pipeline sim             # a stage on the test fixtures
python -m tngxmm.core.runner campaign run --preset v1 --snap 67 --out-root <dir> \
    --targets-csv campaigns/v4/targets_v4.csv --workers 4   # the same, as the cluster job runs it

Presets (src/tngxmm/config.py): v1 (TNG-Cluster, the production campaign), v1_tng300, v1_tng100, v1_tng50, v1_flamingo_l1m8 and v1_flamingo (FLAMINGO L1_m8 and L1_m10), v1_simba, v1_eagle, v1_common (TNG-Cluster under the common emission abundances), v1_flamingo_l1m8_pass1 (one view of every FLAMINGO L1_m8 halo-snapshot under one reference observation, the first pass of the pairing on the fit mass), v1_flamingo_l1m8_pass2 (six icosahedral views of every halo-snapshot, each under a different paired observation of the bank) and v1_flamingo_l1m8_pass2_extra (the same with all 808 observations, fitted with massfit.psf_eval = 'window' and massfit.projection = 'matrix'). The analysis stages run without the cluster from a local data bundle, and tngxmm data fetch downloads what the fits and the mock generation need from the release files of the repository (docs/LOCAL.md).

Layout¶

path

content

src/tngxmm/

the package: one directory per stage (pipeline.py with the Kedro nodes, cli.py), core/ (I/O, cosmology, seeding, paths, provenance), config.py (the spec and the presets), schemas/ (cross-stage tables)

campaigns/

the committed target lists (v4/ replica list, v4_max/ maximal list and matched draws, v4_box/, v4_common/, v4_flamingo_l1m8/ and its pass-1 list v4_flamingo_l1m8_pass1/, realfit_v4/, pilot_v1/, halo_folds/)

conf/

Kedro catalogs, run parameters, generated preset records, and the environments fixtures, realism, smoke, showcase

citations/, CREDITS.md

bibliography fragments per stage; CREDITS.md is generated from them

inputs/

the public table of every literature value the package uses

environment/

pinned environments and the site files, the only place where paths of one machine enter

slurm/

the one-node cluster jobs, submitted through python -m tngxmm.core.runner slurm submit

docs/

the documentation site; docs/dev/ holds the design records (decisions with their evidence, the interface contract, the Kedro map)

tools/, internal/

repository tooling; one-off studies behind the ledger validations (not imported by the package)
