tngxmm.obs.pps_products¶

The image products of the real observations: fetched from the archive, checked, and the summed mosaics built.

The tree of the real observations (site variable TNGXMM_SITE_OBS_IMAGES) holds, per observation and under <catalogue>/<cluster>/, the pipeline products (PPS) the stages read: the per-camera images and exposure maps of the five catalogue bands (IMAGE_1000 … IMAGE_5000, EXPMAP1000 … EXPMAP5000), the EPIC band-8 mosaic (EPX000OIMAGE8000), and two mosaics summed here from the per-camera images, which are not archive products (..._built.FITS):

  • EPX000OIMAGE2000_built the sum of the IMAGE_2000 images, PI (500:1000], 0.5-1 keV;

  • EPX000OIMAGE0520_built the sum of the IMAGE_2000 and IMAGE_3000 images, PI (500:2000], 0.5-2 keV.

catalogue/pps_products.csv lists every file of the tree with its size and sha256 (kind pps or built); for a built mosaic it also has data_sha256, the sha256 of its pixels (big-endian int32), which is what a mosaic summed again is checked against: its header carries the name of the code that wrote it. fetch_products() downloads the PPS files that are missing from the public archive (<base_url>/<obsid>/PPS/<name>, the HEASARC mirror of the XMM-Newton Science Archive), one request at a time through tngxmm.donor_tables.archive.download(), and accepts a file only with the sha256 of the list: the archive is reprocessed from time to time, and a product of another processing is not the product the fits were made from. Such a file, and any the archive no longer serves, is copied from donor, another copy of the tree (the release observations of the repository, tngxmm data fetch --item obs_images). build_mosaics() sums the mosaics again as they were first built and compares each with the list.

The camera exposures summed into a mosaic are those of the band-8 mosaic (its XPROC0 history names them), so the sum has the composition of the archive’s own EPIC mosaic.

The observations added to the bank (tngxmm.obs.extra_observations) are in the same list, under extra/<cluster>/, and go through the same two functions. Their rows were made once from the image sets the candidates were graded on (fetch_unlisted() downloads such a set by the names in the archive’s index, before any checksum of it is known): stage_observations() copies the pipeline products of the pass candidates from <source>/<obsid>/ into the tree and sums the two mosaics, manifest_rows() reads the sizes and checksums of what is then there, and extend_manifest() adds the rows to the list (tngxmm obs stage-extra-images). A copy of the tree made elsewhere needs none of this: tngxmm obs fetch-pps-products fetches the listed files.

tngxmm.obs.pps_products.fetch_products(root=None, *, manifest=None, obsids=None, download=True, donor=None, base_url='https://heasarc.gsfc.nasa.gov/FTP/xmm/data/rev0', opener=None, echo=<built-in function print>)[source]¶

Bring the PPS files of the tree to the list.

A file that is there with the listed sha256 is left alone. A missing or different one is downloaded from <base_url>/<obsid>/PPS/<name> (download) and kept only with the listed sha256; otherwise it is copied from donor when that copy has the listed sha256. Returns the counts (present, downloaded, copied), the files the archive serves in another processing (archive_differs), those it does not serve (archive_absent) and those still missing.

tngxmm.obs.pps_products.build_mosaic(directory, obsid, tag, out=None)[source]¶

Sum the mosaic tag (a key of BUILT_BANDS) of one observation from the per-camera images in directory: the int32 image and the names summed ((None, []) when no image is there). With out the mosaic is written there with the header of the first image and the cards that say what it is.

tngxmm.obs.pps_products.build_mosaics(root=None, *, manifest=None, obsids=None, write=True, echo=<built-in function print>)[source]¶

Sum the built mosaics of the list again and check each against the list.

The pixels of the new sum must have the data_sha256 of the list, else the mosaic is different and not written. A stored mosaic is also compared pixel by pixel with the new sum (identical); a missing one is written (write) and counted built. A mosaic whose per-camera images are not there is no_inputs. Nothing stored is overwritten.

tngxmm.obs.pps_products.fetch_unlisted(obsid, directory, base_url='https://heasarc.gsfc.nasa.gov/FTP/xmm/data/rev0', opener=None)[source]¶

Download the pipeline products of an observation that the list does not hold yet (a candidate) into directory: the names of TREE_PRODUCT in the index of <base_url>/<obsid>/PPS/, one request at a time; a file that is there and not empty is not fetched again. Nothing is checked against a checksum, there is none yet: manifest_rows() records what was fetched. Returns obsid, the number listed by the archive, fetched and present.

tngxmm.obs.pps_products.stage_observations(observations, source_root, root=None, sub=None, echo=<built-in function print>)[source]¶

Put observations that are not in the tree yet into its layout.

observations yields (obsid, cluster name). For each one the products under <source_root>/<obsid>/ are copied to <root>/<sub>/<cluster directory>/ (stage_products(); the directory name is tngxmm.obs.extra_observations.cluster_dir() of the name, sub defaults to the directory of the added observations) and the two mosaics of BUILT_BANDS are summed where they are missing. Returns one row per observation: obsid, name, cluster_dir, n_files and built (both mosaics are there).

tngxmm.obs.pps_products.manifest_rows(root, directories)[source]¶

The rows of the list for the files of some observations as they stand in the tree.

directories yields (obsid, directory relative to the root). A row is made for every pipeline product of that obsid in the directory (TREE_PRODUCT; kind pps) and for its two built mosaics (kind built, with data_sha256), sorted by path. A directory without a built mosaic is an error: the rows of an observation are complete or not made.

tngxmm.obs.pps_products.extend_manifest(rows, manifest=None)[source]¶

Add rows (manifest_rows()) to the list and write it sorted by path. A path that is listed with the same size and checksums is counted present; one listed with others is an error and nothing is written, because the list is what the files of a fit are checked against.
