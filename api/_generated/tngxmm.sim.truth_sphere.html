tngxmm.sim.truth_sphere¶

Spherical hydrostatic truth: every particle within a sphere about the halo centre.

Selected by sim.truth_selection_hse = 'sphere'. Why: the generation computes the intrinsic truth (the HSE masses of tngxmm.sim.compute_hse_mass, the curves of tngxmm.sim.truth_profile) from the halo’s FoF members. At z > 0.7 the FoF gas fills only 0.63-0.82 of the R500c shell, and its members near the group boundary are the denser gas, so the FoF truth falls ~16 % below the spherical (zoom) truth at R500c (docs/dev/DECISIONS.md, “Node-pilot-2b fixes”). The truth is therefore recomputed here from ALL particles (gas, dark matter, stars, black holes) inside a sphere about GroupPos, in every simulation. Photons, maps and the *_tngref columns stay on the FoF gas, and the *_mock estimators keep the mock’s own cells (with the loader ‘fof’, the FoF members inside the sphere; with the production loader ‘cutout’, the whole sphere), which hold every mock cell because the sphere is larger than the mock’s 2 R200c clip).

The stage runs AFTER the generation, per (simulation, snapshot), outside the generation’s memory budget, in three steps:

  1. Select (once per snapshot; persisted). For every target halo the global snapshot indices of the particles within r_cut of GroupPos (minimum-image distance in the periodic box), per particle type, are written to <tree>/truth_cutouts/<sim>/snap_<snap:03d>.h5 (write_cutouts()): sorted int64 per halo and type (delta-encoded), with the centre, radius, box, counts and a sha256 per index array. r_cut = max(f R200c, r_max) with f the spec field sim.truth_sphere_r200c (3 in the campaign) and r_max = 1.02 max(3.15 R500c, 2 R200c) the outermost radius any truth estimator reads (truth_rmax_kpc()).

    • Periodic boxes (TNG300/TNG100/TNG50): a snapshot’s chunk files are consecutive slices of the particle list (FoF order, then the fuzz), not spatial sub-volumes, so a sphere draws from many chunks and the selection of every chunk must be accumulated before any profile is computed. Each chunk’s Coordinates are read once, wrapped into [0, L) and binned on a voxel grid; ONE small cKDTree of the snapshot’s halo centres built with boxsize = L (only the full box is periodic) is queried per occupied voxel, so a voxel knows every sphere that can reach it (SphereSelector); every candidate pair is then decided by the exact minimum-image test |x - c - L round((x - c) / L)| <= r (the brute-force definition, sphere_rows_brute()), so a cell may belong to several halos’ spheres and the result does not depend on how the snapshot is split into chunks (stream_box(), a pool over chunks with a deterministic, chunk-ordered merge).

    • TNG-Cluster: the halo’s ORIGINAL ZOOM (its FoF range and outer-fuzz range of the offsets file, loadOriginalZoom), cut to the sphere (select_zoom(), inside the halo’s truth worker: one zoom per process). Particles of other zooms are never mixed in: each zoom is a separate simulation in the parent volume. The sphere is flagged when it reaches low-resolution dark matter (PartType2 within the truth radius r_max: attribute sphere_contaminated; counts and the nearest distance are recorded either way).

  2. Truth (per halo; resumable). The fields of the selected rows are read (only those rows: block reads of sorted index runs per chunk), wrapped to their minimum image about GroupPos (bit-identical to the generation’s periodic_wrap for every particle that needs no wrap) and handed to compute_hse_truth() through a HaloSource (SphereSource) with selection='sphere' and the mock selection 'fof' (FoF members inside the sphere). The result REPLACES the halo’s truth_profile.h5 (format 3, truth_selection = 'sphere' and the sphere_* attributes; written atomically). A halo whose file already holds the spherical truth of the same spec hash is skipped (the file is the done marker); force recomputes.

    Truth modes (truth_mode, CLI --truth-mode). memory holds every particle of the sphere (the reference above; 0.25-0.4 GB per million particles). streamed reads the sphere’s rows chunk by chunk from the snapshot and accumulates per-shell sums (tngxmm.sim.compute_hse_stream): the same truth (bit-identical except the cumulative particle masses, 1e-10; DECISIONS “Streamed spherical truth”) with a memory that does not grow with the dark matter, ~45 GB for a TNG50 halo-0 sphere (1.1e9 particles) instead of ~450 GB. auto (default) streams a sphere above STREAM_ABOVE_PARTICLES particles; a streamed sphere is never gathered. A streamed file carries the attribute sphere_truth_mode = 'streamed' (absent from an in-memory file).

    Fields come either from the stream itself (mode stream, read in the same pass as the coordinates) or from the persisted cutouts (mode cutouts: the snapshot pass is never repeated); both give the same arrays in the same order, hence the same truth bit for bit (tests/unit/test_sim_truth_sphere.py). With stream_fields=False a stream pass only writes the cutouts and the truth reads its fields from them: a zoom halo by halo (its rows are two contiguous ranges), a box in GATHER passes (gather_fields(): each chunk read once for the union of the rows of a batch of halos whose fields fit gather_gb; a sphere’s rows are scattered over most chunks of a box, so reading them halo by halo would read every chunk once per halo). The production setting for the boxes (memory bounded by gather_gb instead of the snapshot’s whole set of spheres).

  3. Apply (cheap, idempotent): every ok row of the tree’s results CSVs (results_<sim>_snap_<snap>.csv) and its view’s obs_meta.json get the truth columns recomputed from the spherical file (hse_from_truth_profile(), then view_truth_columns() with the view’s z_obs: exactly the generation’s arithmetic). Only values change (no column is added, so a resumed generation appends aligned rows); the first original CSV is kept as <csv>.pre_sphere_truth.bak; obs_meta.json records hse_truth_selection = 'sphere'.

Commands: python -m tngxmm.core.runner campaign truth-sphere (CLI), slurm/truth_sphere.sh (node job), the Kedro node generate_views (after each run’s pool). Acceptance: campaign check C17.

References

illustristng : TNG300-1/TNG100-1/TNG50-1 snapshots, group catalogues and offsets. tngcluster : TNG-Cluster original zooms (offsets OriginalZooms). illustris_python : catalogue reader and the snapshot file layout. scipy : scipy.spatial.cKDTree (periodic tree of the halo centres). h5py, numpy : chunk reads and the cutout files.

sphere_r200c_factor)

COORD_BLOCK_ROWS

GATHER_GB

fields a box gather pass may hold in memory before the truth of its batch [GB]

CUTOUT_DIR

subdirectory of the tree holding the cutout index files and the stage reports

SHAPES

a sphere (the truth) or an axis-aligned cube (the mock gas, tngxmm.sim.mock_cutout); for a cube the stored "radius" is the HALF-SIDE

MOCK_CUTOUT_FORMAT

format of the cube (mock gas) index files, <tree>/mock_cutouts/<sim>/snap_<snap:03d>.h5

BACKUP_SUFFIX

backup suffix of a results CSV before the first application

FILL_SANITY

fill-factor sanity window of the non-SF gas at R500c (campaign check C17); judged only where the cells tile space (tngxmm.ingest.descriptor.volumes_tile: the Voronoi cells of a moving mesh), reported for SPH and meshless runs

TRUTH_MODES

memory (every particle of the sphere in memory, compute_hse_truth(), the reference), streamed (chunked reads, per-shell sums, compute_hse_truth_streamed(); same results, memory independent of the particle count) or auto (streamed above STREAM_ABOVE_PARTICLES)

STREAM_ABOVE_PARTICLES

auto streams a sphere of more particles than this (the in-memory truth peaks at 0.25-0.4 GB per million particles: 3e8 particles ~ 75-120 GB; TNG50 halo 0 has 1.1e9)

BYTES_PER_PARTICLE

bytes per selected particle held by a gather pass (the truth's fields, gidx, in_fof)

class tngxmm.sim.truth_sphere.SphereSelector(centres, radii, box, shape='sphere')[source]¶

Bases: object

Rows of a coordinate block inside each of a set of spheres (periodic box).

One cKDTree of the wrapped sphere centres with boxsize = box (the snapshot’s halo centres; only the full box is periodic). The rows are binned on a grid of cubic voxels (edge about half the largest radius); the tree is queried once per OCCUPIED VOXEL (its centre, radius = largest sphere radius + the voxel’s half diagonal), so every sphere that can reach a voxel is found, however many overlap there; then each candidate (row, sphere) pair is decided by the exact test of sphere_rows_brute(). The result equals the brute-force selection exactly; a row may fall in several spheres. (A query per row instead costs ~1 microsecond per row: 30 s for the 25 M gas cells of a dense TNG300 chunk, against a few seconds.)

shape='box': the “radii” are the half-sides of axis-aligned cubes; the voxel search uses the circumscribed radius (sqrt(3) x the half-side) and the exact test is the per-axis minimum-image bound of sphere_rows_brute().
