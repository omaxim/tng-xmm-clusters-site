tngxmm.ledger.assumptions¶

The assumption ledger: load and validate docs/assumptions/assumptions.yml.

Every number or choice the pipeline makes is one entry of the ledger, with the evidence that makes it defensible in the paper. The ledger is data, not logic: nothing in the pipeline reads it, and it computes nothing. This module only loads the YAML and checks it against the code it describes.

Entry schema (kind decides which evidence block is required):

- id: cosmology.planck15              # unique, [a-z0-9_.]
  kind: literature | validation | instrument | convention
  statement: plain English, what we assume and why
  value: the value as used
  used_by: [cosmology.h0_km_s_mpc, massfit.fit_hydrostatic, params:donors.matched.dz_max]
  code: [src/tngxmm/massfit/fit_qc.py]  # optional: modules that are not Kedro nodes
  evidence:                             # literature: one block per page of a paper (any kind
                                        #   may carry supporting precedent the same way)
    - citation: cosmology_planck2015    # key of citations/*.yml (has an arXiv id when
      page: 32                          #   the proof is a page image)
      needles: ["67.74", "0.3089"]      # exact text boxed on that page
      locator: Table 4, column ...      # section / table / equation
  validation:                           # validation: the decision / report it rests on
    decision: "<heading of a DECISIONS.md section>"
    report: docs/dev/reports/<file>.md  # optional (one of decision / report is required)
    number: "closure real/clean 0.916"
  instrument:                           # instrument: the calibration file or document
    source: "XMM CCF XRT3_XPSF"
    url: https://...
  no_effect: why this has no physics effect   # convention
  open: why no evidence exists yet             # optional; listed in OPEN_ITEMS.md

used_by tokens (resolved by classify_token()):

  • section.field: a field of the campaign spec (tngxmm.config);

  • stage.node: a Kedro node registered in tngxmm.pipeline_registry;

  • params:a.b.c: a key of conf/base/parameters/pipeline.yml;

  • seed_offset / name: the two hashed top-level spec fields.

Coverage rule (tests/unit/test_ledger.py): every hashed (non-runtime) field of the presets in LEDGER_PRESETS appears in the used_by of at least one entry.
