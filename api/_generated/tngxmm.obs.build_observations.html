tngxmm.obs.build_observations¶

The observation table: one row per reference XMM observation (observations.csv).

The reference real sample is the 638 bank observations: the rows of the XMM_ML metadata.csv (PSZ2, CCCP, WtG, LoCuSS pointings) whose obsid has per-camera PPS products and a catalogued mass, plus the ACT DR6 donors of the camera table joined to the DR6 catalogue by name (build_reference_pool(), z_max = 10).

For every observation the table carries the observing conditions a mock view inherits (per-camera live time, FILTER per camera, PN submode, Galactic N_H), the pointing, the catalogue mass with its source_key, the canonical cluster_id (INTERFACES section 2) and subset flags (PSZ2 / ACT DR6 / CCCP / WtG membership, the PSZ2∩XMM + ACT∩XMM “SZ-defined” set, G3 fit set, low-z z-donors). Inputs are the donor tables copied into the repository (obs/catalogue/inputs/, import_donor_tables()) so the table rebuilds anywhere; the per-camera FILTER and SUBMODE come from the PPS headers (tngxmm.obs.read_observation_meta.read_observation_meta()).

References

xmm_mission, xsa : XMM-Newton and the XSA (PPS products and headers). psz2 : Planck Collaboration 2016 (PSZ2; positions and MSZ masses). act_dr6 : ACT DR6 cluster catalogue (positions, z, M500c). cccp, wtg, locuss : weak-lensing samples whose masses the bank metadata carries. hi4pi : HI4PI Collaboration 2016 (Galactic N_H, via heasarc_nh_tool).

tngxmm.obs.build_observations.assign_cluster_ids(obs, psz2, act_dr6, radius_arcmin=2.5)[source]¶

cluster_id per INTERFACES section 2 from the highest-precedence catalogue position.

Precedence PSZ2 > ACT DR6 > other (the metadata / XSA position): a row takes the PSZ2 position of its own PSZ2 name, else of the nearest PSZ2 entry within radius_arcmin; else the ACT DR6 position of its own DR6 name, else of the nearest DR6 entry within radius_arcmin; else its own catalogue position. Two different catalogue entries that truncate to the same id get -b, -c (in obsid order). MCXC is not used: the local MCXC table has no coordinates. Adds cluster_id, cluster_id_source, cluster_id_entry.

THE matching-mass rule (one rule, documented in obs/catalogue/README.md “Matching mass”): an observation is matched on the M500c of the survey that put it in the bank (its sample), read from reference_masses.csv (row = ref_id prefix, table role main, the cluster’s own entry or, for multi-component entries, the component nearest the observation’s catalogue position). A survey that publishes no M500c (WtG: only the 3D mass inside a fixed 1.5 Mpc sphere) is converted from its own measurement with its own model (c200c = 4 NFW; Applegate+14, the convention von der Linden+14b used for WtG M500), never replaced by another survey’s mass, so each mass class stays one calibration. Every matching mass is in the pipeline cosmology (Planck15): lensing NFW masses as the same shear profile, the SZ scaling-relation masses (PSZ2 MSZ, ACT DR6 M500c) re-solved from their own relation for the same observed signal (tngxmm.obs.mass_conversion.sz_m500_to_cosmology(), REFERENCE_LEDGER row 46).

tngxmm.obs.build_observations.matching_masses(obs, ref)[source]¶

Apply MATCHING_MASS_RULE: one row per observation (index of obs) with m500_catalogue_msun and the tngxmm.obs.schemas.OBSERVATION_MASS_COLUMNS, and a list of the rows whose value differs from the metadata mass (before / after).

tngxmm.obs.build_observations.build_observations(inputs, masses='reference')[source]¶

Build the observation table: the 638 reference observations of the bank, then the extra observations (in_bank False; tngxmm.obs.extra_observations.extra_rows()) when inputs carries their tables and masses is 'reference'. The rows of the bank do not depend on the extra ones.

inputs is load_inputs() output. masses='reference' (the only mode for observations.csv) sets the matching mass from inputs['reference_masses'] by MATCHING_MASS_RULE (matching_masses()); masses='metadata' keeps the XMM_ML metadata mass and adds no reference columns: it exists only to give the private reference-mass fetcher the mass-independent columns (cluster ids, positions; see tngxmm.obs.reference_masses.cluster_index()) without a circular dependency. Returns (table, report): the table validates against tngxmm.schemas.tables.OBSERVATION_TABLE (extra columns are stage-internal, declared in obs/schemas.py); the report lists the excluded camera-table obsids with the reason and the cross-checks (header exposures vs the donor exposure table, header PN mode vs the donor PN-mode table).
