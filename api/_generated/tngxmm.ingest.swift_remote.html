tngxmm.ingest.swift_remote¶

Ingest of FLAMINGO runs streamed from the public FLAMINGO data service (hdfstream).

The FLAMINGO data release (Helly et al. 2026) serves every snapshot and SOAP catalogue of the public runs through an HDF5 web service read with hdfstream (a client that returns numpy arrays of any slice or index list of a remote dataset; the lossy SWIFT compression is decoded by the server). This module reads the highest-resolution hydro run L1_m8 (L1000N3600, gas particles 1.3e8 Msun) that way and writes the same materialised canonical cubes as tngxmm.ingest.swift writes for the local L1000N0900 copy. It needs only numpy, h5py and hdfstream (the flamingo_stream environment), and network access (the login node; compute nodes have none).

  • soap_hbt_table(): the halo table of a snapshot from SOAP-HBT (SO/500_crit, SO/200_crit, InputHalos/HaloCentre, centrals InputHalos/IsCentral == 1, the HBT+ track id that follows a halo across snapshots);

  • RemoteCells: the top-level cell index of a snapshot’s virtual file (Cells/; in the virtual file the offsets are global, Cells/Files is 0);

  • ingest_cells(): cell-batched cubes: every top-level cell that overlaps any requested cube is read once (coordinates first; then every other field only for the particles inside some cube, as one index-list request), each cube is cut and written; resumable (halos already in the output are skipped), sha256 per dataset (tngxmm.ingest.cube_io), the remote paths, snapshot and SOAP version in the file attributes.

The gas conversions are those of tngxmm.ingest.swift.canonical_gas_arrays() (descriptor flamingo_l1m8). Politeness: one request at a time, no parallel streams.

References

flamingo (simulation), flamingo_dr (data release and the hdfstream service), hdfstream (client), swift (snapshot format, cells), soap (halo catalogue), hbtplus (HBT+ halo finder and track ids).

tngxmm.ingest.swift_remote.ingest_remote(cells, rows, out_path, *, half_side_r500, snap, h, remote, soap_meta, kinds=('dm', 'stars', 'bh'), sim='flamingo_l1m8', echo=<built-in function print>, log_every=1, r200_cover=3.0)[source]¶

The canonical cubes of rows (soap_hbt_table()) from the remote snapshot cells, written to out_path (one HDF5 file per snapshot, tngxmm.ingest.cube_io); halos already in the file are skipped. The half-side is max(half_side_r500 R500c, 1.001 r200_cover R200c), so that the truth sphere of sim.truth_sphere_r200c = r200_cover lies inside every cube (it matters for halos with R200c / R500c above 5.66 / 3 = 1.89). Returns one progress record per written halo (seconds, bytes streamed so far, counts).

tngxmm.ingest.swift_remote.stream_missing(run, spec, desc, options, echo=<built-in function print>)[source]¶

Stream the planned halos of one run (one snapshot of a preset) that its cube file does not hold yet, and return their number.

The planned halos are those of the run’s targets file. Their SOAP rows come from soap_<snap>.csv under options['soap_dir'] (default <cube_root>/<sim>/soap), which is fetched when it is not there (write_soap_tables(), centrals with M500c >= options['soap_m500_min'], default 1e14 Msun). The cubes are written by ingest_remote() with the half-side options['half_side_r500'] (default sim.mock_box_r500) and the cover sim.truth_sphere_r200c, as the separate streaming step writes them; a halo already in the file is not read again, so an interrupted run goes on where it stopped. Needs the network.

tngxmm.ingest.swift_remote.ingest_run(run, spec, desc, options, echo=<built-in function print>)[source]¶

The canonical cubes of one planned run (one snapshot of a preset) of a streamed simulation.

By default they must already exist: the streaming is a separate step (python -m tngxmm.ingest.swift_remote cubes, on a machine with the network; the sample rule is internal/ledger_tests/multisim/l1m8_sample.py) and this function checks them (tngxmm.ingest.cube_io.verify_run()). With options['stream_missing'] the planned halos that the cube file lacks are streamed first (stream_missing()), so that a run on a machine with the network fetches what its targets need and nothing else; the check is the same, and the record gains n_streamed. The loader of the Kedro node ingest.build_canonical_cubes for the descriptor flamingo_l1m8 (tngxmm.ingest.loaders).
