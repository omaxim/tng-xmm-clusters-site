tngxmm.core.membudget¶

Node-wide memory budget of the campaign workers: one token pool (GB) shared by every worker of every pool on the node, the per-halo memory estimate, peak-RSS reporting.

Why: the gas-load slot (tngxmm.core.pool.gas_load_slot()) bounds the number of CONCURRENT RAW READS, not the memory a halo task holds after its reads (the mock gas cells, the *_tngref and map cells, the truth particles of every type). A node pilot with two lanes of 40 + 28 workers was OOM-killed after 5 minutes at 252 GB: every worker held its arrays at once. The budget bounds the SUM of the estimated peaks of the tasks that run their heavy steps at once.

Mechanism (deadlock-free, cross-process):

  • the pool is a small JSON state file ($TNGXMM_MEM_BUDGET_FILE, under the job’s scratch directory) guarded by a POSIX lock on a companion .lock file, so every process of the job on the node (the workers of both lanes, which are separate campaign run processes) shares it; the total is $TNGXMM_MEM_BUDGET_GB;

  • a halo task acquires its estimated PEAK before its first raw read (and before the gas-load slot: budget first, slot second, so a slot holder never waits for the budget), shrinks the grant to its per-view level once the halo-level steps (gas, tngref cells, truth) are done, and releases everything at its end, also on an exception; a task never waits while it holds tokens (a grant only shrinks), so there is no hold-and-wait and hence no deadlock;

  • a request larger than the whole budget is clamped to the total: it waits until it alone holds the pool (it runs alone; estimate_halo() reports the unclamped estimate);

  • waiters are served first-come-first-served when the oldest one has waited longer than starvation_s (before that a smaller task may overtake a big one that does not fit yet, which keeps the node busy);

  • grants of dead processes (a worker killed by the OOM killer, a crashed lane) are dropped by the next caller (pid + process start time, so a reused pid is not mistaken for the holder).

Without $TNGXMM_MEM_BUDGET_GB nothing changes (no budget, no extra key in any product; except that TNGXMM_MEM_PROBE=1 adds a memory block to obs_meta.json): the fixture regressions run unbudgeted.

The estimate (estimate_halo()) is linear in the FoF particle counts of the group catalogue (GroupLenType), per heavy step, with per-particle coefficients calibrated by RSS measurement (VmHWM reset through /proc/self/clear_refs) on halos spanning the mass range (docs/dev/DECISIONS.md, memory budget).

References

Nelson et al. 2019 (IllustrisTNG data release: GroupLenType of the FoF catalogue).

tngxmm.core.membudget.LEVELS = {'gas': {'c': 0.64, 'n0': 405.0}, 'instrument': {'c': 3.57, 'n0': 123.0, 'p': 0.122}, 'photons': {'c': 2.06, 'n0': 395.0}, 'tngref': {'c': 0.53, 'n0': 303.0}, 'truth': {'c': 0.54, 'n0': 428.0}}¶

memory level of each heavy step of a halo task above the idle worker’s RSS: c [GB] + n0 [bytes per FoF gas cell] + p [GB per unit of the photon proxy, photon_proxy()]. A level includes what the earlier steps still hold (the mock gas cells through the whole task, the tngref / map cells after their read). gas: mock FoF gas read + emission; tngref: the temet-exact and map cells; truth: every particle type + the HSE / profile computation (n0 also tracks the DM and star counts: n1 = 1.3-1.4 n0, n4 = 0.1-0.25 n0 over the target lists); photons: per view map projection, photon generation, absorption; instrument: per view instrument stage and photometry (the event lists scale with the photons). Calibrated on 8 halos (n0 2.8e6-5.2e7, TNG-Cluster z = 0-1.2, TNG300, TNG100): least-squares line raised to cover every measured point.

Memory estimate of one halo task [GB above the idle worker] from its FoF counts (GroupLenType or a group record) and the photon proxies of its views (photon_proxy(); None: P_FALLBACK): every step’s level c + b * n0 + p * P (c: constant, n0: FoF gas count, P: the photon proxy, the maximum of the list if several; b, p: the per-particle and per-proxy coefficients of LEVELS; the arrays the earlier steps still hold included), times safety; peak their maximum, views the level of the per-view phase (photons, instrument).

class tngxmm.core.membudget.TaskMemory(budget, est, label='')[source]¶

Bases: object

The memory scope of one halo task in a worker: the lazy budget grant (taken by claim() before the first raw read), the shrink to the per-view level (shrink_to_views()), the peak-RSS report (report()).

claim()[source]¶

Acquire the task’s peak estimate [GB] from the budget, blocking until it is free; does nothing without a budget, an estimate or when already holding a grant. A failure while waiting withdraws the waiting entry.

shrink_to_views()[source]¶

Reduce the held grant to the estimate of the data that stay resident while the views are made (est.views [GB]), freeing the difference for other tasks.

close()[source]¶

End of the task (its arrays freed and the heap trimmed): record the worker’s resident memory now, then give the grant back.

report()[source]¶

{rss0_gb, peak_rss_gb, task_peak_gb, ...}: the worker’s RSS at the task start, its peak RSS during the task (VmHWM since the start) and their difference, with the estimate and the budget grant (GB, wait s).
