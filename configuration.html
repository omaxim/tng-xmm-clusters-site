Configuration¶

The configuration has four layers, from the physics down to the machine.

  1. The campaign spec and its presets (src/tngxmm/config.py) are the physics of a run. Every number is a field with value, unit, reading module and citation. The spec is hashed: a different value is a different campaign.

  2. The run options (conf/base/parameters/pipeline.yml) are workers, paths and sampler settings; they are the CLI defaults, so kedro run and tngxmm <stage> agree. They are not physics and are never hashed.

  3. The Kedro environments and globals (conf/<env>/) say where the data live and which options an acceptance run changes.

  4. The site (environment/sites/*.env and the TNGXMM_* variables) says where this machine keeps things.

Presets¶

A preset is a complete CampaignSpec. The field defaults are the v1 values, except the conditions rule donors.observing_conditions, which v1 and every other preset set. The TNG box presets change only the simulation; the presets of FLAMINGO, SIMBA and EAGLE also name a descriptor (sim.source), read the snapshots nearest the v1 redshifts, drop the temet reference and read materialised cubes (runtime.cube_store = 'canonical'); v1_common is v1 under the common emission at every TNG snapshot from z = 1.5 to 0; v1_flamingo_l1m8_pass1 (config.PASS1_PRESETS) is v1_flamingo_l1m8 with one projection, the conditions rule donor (each view under its donor as it is, no draw among neighbours and no jitter), its own stream key and no stored photon lists (runtime.drop_events); v1_flamingo_l1m8_pass2 (config.PASS2_PRESETS) is the pass-1 preset with the six icosahedral projections (sim.projection = 'icosahedral6', views 0 to 5) and its own stream key; v1_flamingo_l1m8_pass2_extra is that preset with donors.reference_sample = 'bank638+extra', massfit.psf_eval = 'window' and massfit.projection = 'matrix' (The PSF on the mask window and the projection in one product: what changes, by how much, how fast). The spec hash (CampaignSpec.spec_hash) is the sha256 of the sorted JSON of every non-runtime field; the generation hash leaves the massfit section out as well. The packaged observation table enters the hash by the columns the stages read (config.OBSERVATION_COLUMNS, 38 of its 70; rows by obsid, numbers as their shortest round-trip text), so a rebuild that changes only the other columns moves no hash. Under donors.reference_sample = 'bank638' (every preset but v1_flamingo_l1m8_pass2_extra) only the rows with in_bank True are hashed, so the 170 observations added on 2026-11-25 changed no existing hash; 'bank638+extra' hashes all 808 rows. python -m tngxmm.config --show v1 prints the fields, --hash v1 the hash; Kedro takes the preset as params:preset and resolves it with config.get_preset, so no node holds a copy of the physics.

Spec fields¶

Generated from the field metadata (config.P), with the values of v1. “Hashed only when set” fields join the hash only when not None, so adding one leaves every older preset’s hash unchanged.

Run options and parameters in Kedro¶

params:preset is the one preset of a run. params:<stage>.<key> are the options of pipeline.yml; tests/unit/test_kedro_pipelines.py checks that no option restates a spec field with another value (deliberate deviations are listed there). Parameters of an environment merge into base key by key (merge_strategy: soft): an environment states only what it changes, a scalar or list is replaced, a mapping is merged, key: null clears.
