INTERFACES: the contract between the stages¶

The code is the contract wherever both exist: src/tngxmm/schemas/, src/tngxmm/config.py, src/tngxmm/core/, src/tngxmm/cli.py, src/tngxmm/cites.py. This document explains it and records the decisions the code cannot express. A change of a table, an id, a file name or a seed message is a change of the contract: it goes with a new version of the package (CHANGELOG.md) and with the tests that pin it.

1. Package skeleton, CLI and registration points¶

  • One installable src-layout package src/tngxmm/, Python ≥ 3.10, MIT. pyproject.toml: [tool.kedro] package_name = "tngxmm", source_dir = "src"; console script tngxmm = tngxmm.cli:main. Importing tngxmm needs only click; every scientific import (numpy, astropy, pandas, kedro, torch) is deferred to the function that uses it. A unit test enforces this.

  • Frozen stage list (tngxmm.STAGES, data-flow order): ingest sim instrument donors obs photometry massfit bank embed ml viz (ingest added on the branch multisim, DECISIONS “Multi-simulation pipeline”). Kedro namespace = stage, so node names read massfit.fit_hydrostatic.

  • Per-stage registration points (owned by the stage’s workstream; no shared-file edits needed to add things): src/tngxmm/<stage>/cli.py (click group named after the stage, exported as group), src/tngxmm/<stage>/schemas.py (stage-internal TableSchemas in TABLES), src/tngxmm/<stage>/pipeline.py (NODES list + create_pipeline()), conf/base/catalog/<stage>.yml, citations/<stage>.yml.

  • Module naming <stage>/<verb>_<object>.py.

  • CLI (root cli.py): tngxmm <stage> ... for the stages, and the groups campaign (run, truth-sphere, check), certify, data, cite, freeze, ledger, slurm, validation; tngxmm --help lists them. The ml stage has no command. Views are generated by tngxmm campaign run and selected by the targets table. tngxmm viz --mermaid [--check] [--stdout] and --graphviz PATH export the pipeline graph; tngxmm cite [--lint] [--list] [--json] [--credits FILE] works on the citation keys; tngxmm freeze check is gate Z (core/freeze.py).

  • Kedro: src/tngxmm/settings.py, src/tngxmm/pipeline_registry.py (one pipeline per stage + __default__). Nodes are built with tngxmm.cites.stage_node(func, inputs, outputs), which sets the node name to the function name and the tags to cite.<key> (Kedro accepts only [\w.-]+; cite:<key> is invalid). Catalog fragments conf/base/catalog/<stage>.yml are loaded by Kedro’s default catalog*/** pattern. Parameters conf/base/parameters/<preset>.yml are GENERATED (make params) and each holds one top-level key campaign_<preset> because Kedro rejects duplicate keys across parameter files; no node reads them (nodes call config.get_preset).

  • Citations: the decorator @cites("key", ...) is the single source; every module ends with __cites__ = collect_cites(__name__) or declares __cites__: list[str] = []; tngxmm cite --lint fails on a missing or under-declared __cites__ and, once citations/*.yml exist, on unknown keys. Keys match [a-z0-9][a-z0-9_.-]*.

  • Flowchart: tngxmm viz --mermaid rewrites the fenced block between <!-- pipeline:start --> and <!-- pipeline:end --> in README.md; make viz-check fails when the block is stale.

  • Local CI: make check PY=<python> = ruff (correctness rules) + hygiene scan + citation lint + schema tests + pytest -m "not cluster and not e2e". pytest markers: unit, e2e, cluster.

3. Per-camera product contract (src/tngxmm/schemas/products.py)¶

  • 30 files per view = 3 cameras × {IMAGE_, EXPMAP} × 5 bands, gzipped FITS: P<obsid>{PNS003,M1S001,M2S002}{IMAGE_,EXPMAP}{1000,2000,3000,4000,5000}.FTZ. Bands [keV]: 1000 = 0.2–0.5, 2000 = 0.5–1.0, 3000 = 1.0–2.0, 4000 = 2.0–4.5, 5000 = 4.5–12.0 (the PPS names, schemas.products.BANDS_KEV_SAS; the fits read bands 2000–5000 only). A camera absent from the donor has no files (10 per simulated camera).

  • IMAGE_: int32 counts; EXPMAP: float32 vignetted exposure [s] at the band mean energy, same grid (4″/px, 648²; PPS-like TAN WCS centred on the cluster, CRVAL = (150.0, +2.0) for mocks).

  • Required header keys on every product: INSTRUME (EPN/EMOS1/EMOS2), FILTER, EXPOSURE (camera live time [s]), EMIN, EMAX, and the TAN WCS (CTYPE1/2, CRPIX1/2, CRVAL1/2, CDELT1/2). Additionally on MOCK products: VIEW_ID, POSANGLE, SUBMODE, TNGXVER (package version), SPECHASH. On every EXPMAP: EXPFIX = 'rot-sign-2026-10-06'.

  • SUBMODE per camera: with instrument.pn_submode_header = 'per-donor' every camera’s products carry the donor’s SAS submode of THAT camera: PN from the donor package pn_submode (unknown -> PrimeFullWindow, as its out-of-time fraction), MOS1/MOS2 from submode_mos1/submode_mos2 (targets tables -> core.pool.replica_package -> instrument_view_kwargs(...)['camera_submodes'] -> run_xmm_simulator(camera_submodes=...); values seen: PrimeFullWindow, PrimePartialW2, PrimePartialW3, FastUncompressed). A MOS camera without a donor mode keeps PrimeFullWindow with the comment MOS mode not in the donor record: assumed. Keys RDWINDOW (instrument.readout_windows: full-frame | donor; also on the merged image) and WINAREA (per camera, detector area read out [arcmin²]). Under readout_windows = 'donor' the IMAGE events and the EXPMAP of a camera share the window footprint of its SUBMODE (instrument/readout_windows.py; geometry and its check against the PPS exposure maps in DECISIONS.md, “Readout windows”). Under instrument.active_ccds = 'donor' every camera images the CCD segments its donor had (instrument/active_ccds.py, data-package tables donor_active_ccds.csv and epic_ccd_maps.fits), events and EXPMAP alike, the readout window on top; per-camera keys CCDRULE (donor), CCDLIST (comma list of segments: CCD numbers 1–7 (MOS) / 1–12 (pn) and 14 = the outer stripe of MOS1 CCD4 blanked on board since 2012-12-11) and CCDSRC (pps-expmap: measured on the donor’s PPS exposure map; date-rule: the epoch of the permanent MOS1 losses, for a donor without a map). Absent under 'mask' (the packaged 2018 masks).

  • SAS-ready products (instrument.product_bands = 'pps-1-5', pn_band1_events = 'single-pixel', sas_headers = 'on'). The pn band 1 follows the PPS image selection PATTERN == 0 && RAWY > 12 (header PATTSEL, SINGLEFR, RAWYMIN): the mocks carry no event patterns, so each event is kept with the CCF single-pixel fraction FRAC_S/FRAC_SD at its energy and the events within 12 rows of the readout node are dropped; the pn QPB of 0.2–0.5 keV keeps the single-pixel fraction of the filter-wheel-closed events; the EXPMAP is unchanged (eexpmap evaluates neither PATTERN nor RAWY). Header keywords SAS reads, on every IMAGE and EXPMAP (instrument/sas_headers.py): TELESCOP = 'XMM', OBS_MODE, DATAMODE = 'IMAGING', OBS_ID / EXP_ID / EXPIDSTR / DATE-OBS of the DONOR exposure (MOCK = T; EXP_ID a numeric string <obsid><nnn>), RA_PNT / DEC_PNT the sky position of the optical axis (pixel OPTAXX/OPTAXY), PA_PNT = (POSANGLE + 114.2157) mod 360 (the packaged masks have the orientation of obsid 0827340901, PA_PNT 114.2157; the roll is counter-clockwise on the north-up image; DECISIONS.md, “SAS-ready products”), ONTIMEnn (live time of each imaged CCD, nn = CCD number), for the pn FRMTIME [ms] and TIMEDEL [s], and the PPS physical sky-coordinate keywords (REFX/REFY*, CTYPEnL, … : physical pixel 25921 on the optical axis). Every integer keyword beyond 32 bits (VIEWSEED) is a string (the SAS DAL cannot parse 64-bit integers); the TAN WCS (cluster at CRPIX) is unchanged. With instrument.pn_edge_rows = 'drop' the pn events within 12 rows of the readout node (RAWY <= 12) are removed in EVERY band, as the real cleaned pn event lists have none (header PNEDGE); the EXPMAPs are unchanged, because the PPS exposure maps (eexpmap, which evaluates neither PATTERN nor RAWY) still expose those rows. Source detection (instrument/sas_detect.py, Kedro instrument.run_sas_detection) builds the calibration index file with cifbuild at the FIXED analysis date CCF_ANALYSIS_DATE (the day the Valid CCF set was downloaded; mocks and real data alike; recorded with the CCF manifest sha256 in sas_detect/provenance.json).

  • Merged products per mock view: image_merged.fits (0.5–2 keV integer counts, 648² at 4″, header EMSCE001..N live times, POSANGLE, CLUSTX/CLUSTY, DITHERX/DITHERY), image_merged_cov.fits (coverage), obs_meta.json (provenance; the view-table row).

  • Intrinsic reference map per view (sim.tngref_map = 'on'; sim/project_tngref_map.py): tngref_sb_map.fits, the TNG-Cluster official X-ray map (postprocessing/projections/gas-xray_lum_<band>kev__2r200_d=r200.<snap>.hdf5, temet catalog/maps.py:projections) recomputed for the view. Empty primary HDU (common header, BANDS) + one lossless GZIP_2 tile-compressed float32 image per band of sim.tngref_map_bands (EXTNAME = 'SB_<band>KEV': 0.5–5.0 and 0.5–2.0 keV), sim.tngref_map_npix² (2000²). Values log10 SB [erg/s/kpc², physical kpc], -inf where no cell emits; luminosity = temet-exact (temet’s table, every cell of sim.lx_reference_gas: ‘fof’, the FoF group; ‘zoom’: the original zoom, the official cell set; no gas cut, at their periodic minimum image about GroupPos), rest-frame band ÷ (1+z_snap) (LUMCONV). Intrinsic hydrostatic truth columns¶

ONE methodological line. The headline m500c_hse_msun is the estimator barnes21_nosf_fit_mu (sim.hse_pressure = 'thermal-fit-mu'): Barnes et al. (2021, MNRAS 506, 2533) secs. 2.1.5 and 2.4 – 50 linear shells over 0-1.5 R500c, the shell gas density and the shell mass-weighted quantity fitted with the Vikhlinin et al. (2006) forms and differentiated analytically – with ONE deviation of ours: Barnes et al. state no gas cut for the 3-D profiles (their cuts belong to the synthetic images), we exclude the star-forming cells (their temperature is the effective equation-of-state value of the TNG star-formation model) – with the thermal pressure of each cell as simulated: the mass-weighted <T/mu> with each cell’s own mean molecular weight mu = 4 / (1 + 3 X_H + 4 X_H x_e) replaces the temperature and the fixed mu = 0.59. The mass is M(<r) = -(k r / (G m_p)) <T/mu> (dln rho/dln r + dln <T/mu>/dln r); M500c,HSE is read at the INNERMOST downward crossing of M(<r) / (4/3 pi r^3) = 500 rho_c(z_snap) beyond 0.4 R500c (hse_crossing counts the crossings; fit-failed when the Vikhlinin fits did not converge). The shell density is the density of the gas present (hse_shell_density = 'filling', shells filled below 10 % omitted); the particles are those within a sphere about the halo centre (the spherical truth stage). The same estimator with the assumed mu = 0.59 (barnes21_nosf_fit) is not emitted (no column, no truth-profile dataset; the code is behind compute_hse_truth(mu059_fit=True) for one unit test). The finite-difference twin without star-forming gas (barnes21_nosf, mu = 0.59) is not emitted either (no column, no truth-profile dataset, not a selectable headline; behind compute_hse_truth(nosf_fd=True), default off, for unit tests only).

Sentence for a paper: “The intrinsic hydrostatic mass of each simulated cluster follows Barnes et al. (2021): from the shell gas density and the mass-weighted temperature-to-mean- molecular-weight ratio in 50 linear radial shells out to 1.5 R500c, fitted with the Vikhlinin et al. (2006) parametrisations and differentiated analytically, using the thermal pressure of each gas cell as simulated (its own mean molecular weight, not an assumed mu = 0.59). Unlike Barnes et al., who apply no gas cut to the three-dimensional profiles, we exclude star-forming gas cells, whose temperature is the effective equation-of-state value of the TNG model rather than a physical one. M500c,HSE is the mass inside the innermost radius beyond 0.4 R500c at which the mean enclosed density falls to 500 times the critical density of the snapshot.”

All 67 truth columns (compute_hse_mass.TRUTH_COLUMNS), classified. Each estimator <k> has the three columns m500_hse_<slug>_msun (self-consistent M500 at 500 rho_c(z_snap)), mhse_<slug>_r500c_over_m500c (M_HSE(<R500c) / M500c) and mu_hse_<slug> (the mu used; NaN: none).

4.9 Canonical datasets (src/tngxmm/ingest/schema.py, format tngxmm-canonical-1)¶

What the ingest stage writes for every simulation and the later stages read (DECISIONS, “Multi-simulation pipeline”).

  • Simulation descriptor (src/tngxmm/ingest/descriptors/<name>.yml, ingest.descriptor): name, family (tng | swift), base path, zoom or box, box size, cosmology, hydro scheme, snapshots with their redshifts, halo catalogue and mass definitions, the canonical field mapping with its conversions, temperature, ionisation, star-forming, wind and net-heating rules, metallicity source and element list, citations, status (production | validation). 6. RNG contract (src/tngxmm/core/rng.py)¶

  • One scheme, sha256-v1: every random draw of a view comes from an independent stream seeded from the view’s coordinates. The seed is the first 8 bytes (big-endian) of the SHA-256 of '{namespace}|rng|sha256-v1|{campaign}|{sim}|snap={snap:03d}|halo={halo_id}|view={view}|real={realisation}|{purpose}|{camera or "-"}', masked to 63 bits. campaign is the stream key sim.rng_campaign (else the preset name); realisation 0 is the production draw and k >= 1 a re-observation of the same view (the instrument replay); namespace is tngxmm.

  • Closed vocabulary of purposes. View level: z_obs, donor, photon_counts, photon_energy, photon_position, absorption, posangle, dither, partition, agn_sky, global_legacy (seeds the global numpy stream for library code that draws from it), conditions (the conditions-donor draw and its jitter, instrument.conditions_donor; only drawn under that switch). Donor level (seed_for_donor, '{namespace}|rng|sha256-v1|{campaign}|donor={obsid}|{purpose}'): conditions (the permutation of a donor’s conditions candidates shared by its replicas). Per camera (MOS1, MOS2, PN): psf, rmf, background_sky, agn_counts, oot, background_qpb. An unknown purpose, or a camera on a view-level purpose, raises.

  • Under the per-projection conditions draw (release 1.2) the conditions donor of view v depends on the first integer of the conditions stream of every earlier view of the same halo-snapshot (same key, simulation, realisation and scheme; conditions_donor.sibling_conditions_rng). No stream or purpose is added and the view’s own conditions stream is used as before: one integer for the candidate, then the jitter. With a single candidate numpy draws nothing for the range of one, and the jitter starts at the stream’s first number (under the release 1.1.1 draw as well).

  • ViewStreams is what the per-view generation and the instrument stage receive: one cached numpy.random.default_rng(seed_for(...)) (PCG64) per (purpose, camera). fingerprint() hashes the final state of every stream, a cheap draw-order check; provenance() records the scheme, the stream key, the realisation and the fingerprint in obs_meta.json.

  • The call order and the conditional skips of every draw are part of the contract: a changed draw order changes every product. Known-answer seeds and the fingerprint of a view are unit-tested.

  • SPLIT_SEED = 7777 is the frozen seed of the train/val/test split by zoom target.

9. Bank format¶

  • Canonical stored science artefact: the merged 0.5-2 keV mosaic as uint16 counts (+ gzip, ~66 KB), full 648² frame, in the mosaics assets of the data package.

  • The bank render (inferno RGB, normalize_image stretch, 640² native crop) is DERIVED deterministically from the mosaic by tngxmm bank render; it is what DINOv3 consumes and it is not shipped.

  • The render PNG bytes and the embedding vectors of the frozen bank entries are the reference of the bank tests.

10. Working rules for shared files¶

  • The shared files are core/, config.py, schemas/, pyproject.toml, the root cli.py, .githooks/ and .gitignore. A change to one of them is a change of the contract: it is made once, with its tests, and announced in CHANGELOG.md.

11. Environments (environment/README.md)¶

  • Three pinned lock files: environment/sim.lock.txt (python 3.10.9, numpy 1.26.4, pyxsim 4.4.2, soxs 4.8.5, yt, xmm_simulator 0.2.0 @ upstream 9fdedb4e + environment/patches/ for the scipy interp2d removal and the MOS QE NaN fix; the stale upstream build/lib is removed before the build), massfit.lock.txt (numpy 2.2.6, mbproj2d 0.2 @ ff497101, pyfftw, nlopt, emcee; GCC 12.1.0; HEASoft 6.35.1 apptainer image) and embed.lock.txt (72 packages layered on the anaconda module’s 317; torch 2.5.1+cu121, transformers 4.57.3). Random draws are identical under numpy 1.26.4 and 2.2.6, so the split exists for dependency pins, not for reproducibility.

  • environment/bootstrap.sh builds the shared environments under $TNGXMM_SITE_PTMP/tngxmm_env/{sim,massfit,embed} (idempotent; --dry-run resolves everything).

  • Thin per-worktree venv: environment/thin_venv.sh <shared-env> <worktree> [<id>] [--with-kedro]: a .pth file adds the shared env’s site-packages and the user site is disabled (--system-site-packages only for embed, module torch). environment/runtime_env.sh sets TMPDIR, PIP_CACHE_DIR, MPLCONFIGDIR, XDG_CACHE_HOME (soxs data symlinked back to ~/.cache/soxs), HF_HOME/TORCH_HOME (the gated DINOv3 cache), ATOMDB (must be set BEFORE import xmm_simulator), CCF_PATH, MBPROJ_* and the apptainer PATH.

  • XSPEC: environment/check_xspec.sh prints RESULT: XSPEC OK; XSPEC 12.15.0; the image’s default APEC 3.0.9 gives NaN at kT 7.9-8.1 keV, the 3.1.3 tables at MBPROJ_APECROOT are finite; /vera/ptmp is visible inside the container, /vera/u is not.

  • Login-node etiquette: at most 4 cores, OMP_NUM_THREADS=1, fixtures only.
